## 1. 분류 평가 지표

좋은 모델의 기준은 **먼저** 정합니다. 무엇을 예측하는지, 어떤 실수가 더 큰 손실을 만드는지를 정한 뒤 주 지표 하나와 보조 지표를 함께 봅니다.

### 1-1. 혼동행렬 (Confusion Matrix)

이 수업에서는 **실패(1)를 양성**으로 고정합니다.

| 실제 \ 예측 | 예측 0 (성공) | 예측 1 (실패) |
|---|---|---|
| 실제 0 (성공) | TN: 정상 통과 | FP: 오탐 |
| 실제 1 (실패) | FN: 놓침 | TP: 실패 발견 |

- `confusion_matrix(y, pred, labels=[0, 1]).ravel()` → **TN, FP, FN, TP** 순서
- `labels=[0, 1]`로 행·열 순서를 고정합니다.

### 1-2. 네 가지 지표

| 지표 | 공식 | 확인할 질문 |
|---|---|---|
| Accuracy | (TP + TN) / 전체 | 전체 예측 중 맞힌 비율은? |
| Precision | TP / (TP + FP) | 실패라고 예측한 것 중 실제 실패는? (경고의 신뢰도) |
| Recall | TP / (TP + FN) | 실제 실패 중 얼마나 찾았는가? |
| F1 | 2 × P × R / (P + R) = 2TP / (2TP + FP + FN) | 두 비율의 균형은? |

- **Precision과 Recall은 분모가 다릅니다.** 예측한 양성 집합과 실제 양성 집합은 서로 다른 집합입니다.
- **F1은 조화평균**이므로 한쪽이 매우 낮으면 함께 낮아집니다. TN을 직접 반영하지 않으며 업무 비용 전체를 대신하지 않습니다.
- 예시 (TN 10, FP 4, FN 4, TP 2): Accuracy 0.600, Precision = Recall = F1 = 0.333
- `zero_division=0`은 분모가 0일 때의 **기록 규칙**입니다. 양성 예측이 0건이라는 상황 자체도 함께 적습니다.

> **주의 (Accuracy의 함정):** 실제 실패 6건·성공 14건에서 모두 성공으로 예측하면 Accuracy는 0.70이지만 Recall은 0, 실패 발견은 0/6입니다. "60% 정확도"와 "실패 60% 발견"은 다릅니다.

### 1-3. 지표 선택

| 상황 | 우선 검토 | 같이 확인할 것 |
|---|---|---|
| 실패를 놓치면 손실이 큼 | Recall 또는 재현율 제약 | 오탐 수, 처리 인력, Precision |
| 경고마다 사람의 확인 비용이 듦 | Precision 또는 경고 비용 | 놓친 실제 실패 수, Recall |
| 두 오류를 함께 줄이고 싶음 | F1 | FP·FN 건수와 실제 비용 |
| 연속적인 실행시간 예측 | MAE·RMSE | 단위(ms), 큰 잔차, 자료 범위 |

> 지표 선택은 정답을 찾는 문제가 아니라 **실패의 비용과 운영 조건을 명시하는 일**입니다. 같은 자료, 같은 양성 라벨, 같은 기준에서만 모델을 비교합니다.

## 2. ROC-AUC와 임계값

### 2-1. 점수·확률·클래스 구분

| 구분 | 설명 |
|---|---|
| `predict_proba` | 클래스별 추정 확률. 실패(1)의 열은 `classes_`로 확인 |
| 판단 정책 | 기본: p > 0.5이면 실패(1), p = 0.5이면 성공(0) |
| ROC-AUC 입력 | **연속 점수**를 넣음 (0/1 최종 클래스만 넣지 않음) |

- 임계값은 모델·자료와 함께 **평가 전에 고정할 설정**입니다.
- 추정 확률 0.8은 "반드시 80% 확률로 실패한다"는 보장이 아닙니다.

### 2-2. ROC 곡선

| 축 | 공식 | 의미 |
|---|---|---|
| 가로 FPR | FP / (FP + TN) | 성공 요청 중 잘못 경고한 비율 |
| 세로 TPR | TP / (TP + FN) | 실제 실패 중 찾아낸 비율 (= Recall) |

- 임계값을 바꾸면 곡선 위의 점이 이동합니다. 좌상단에 가까울수록 좋습니다.
- **AUC = 곡선 아래 면적 = 양성 점수가 음성 점수보다 높은 쌍의 비율**
  - 예: 양성·음성 2×2 = 4쌍 중 3쌍에서 양성 점수가 높음 → AUC 0.75

### 2-3. 임계값을 바꾸면?

같은 점수로 임계값만 바꾼 설명 예시입니다. (비용 `FP + 5×FN`은 설명용 가정)

| 임계값 | FP | FN | F1 | 비용 | AUC |
|---|---|---|---|---|---|
| 0.5 | 0 | 1 | 0.667 | 5 | 0.75 |
| 0.3 | 1 | 0 | 0.800 | 1 | 0.75 |

→ **AUC는 그대로**이고, FP·FN·F1이 바뀝니다. 점수의 순위가 같기 때문입니다.

> **주의:**
> - AUC는 순위 평가입니다. 임계값에서의 경고 수·Precision·Recall도 함께 확인합니다.
> - **AUC 0.786 ≠ 실패의 78.6%를 발견했다는 뜻**입니다. 실제 발견 비율은 Recall입니다.
> - 불균형 자료에서는 실제 양성 수와 PR 관점도 함께 봅니다.
> - 한 클래스만 있는 자료는 AUC를 계산할 수 없습니다. 0으로 위장하지 말고 `None`으로 표시하고 실제 양성 수를 기록합니다.
> - 확률의 보정과 운영 비용은 별도 문제입니다. 좋은 AUC만으로 배포를 결정하지 않습니다.
> - **test F1을 높이는 임계값을 고르면 test를 모델 선택에 쓴 것**이 되어 최종 독립 평가가 아니게 됩니다.

## 3. 회귀 지표와 교차검증 점수 해석

### 3-1. RMSE와 MAE

| 지표 | 계산 | 특징 |
|---|---|---|
| MAE | 절대오차의 평균 | 평균적인 오차 크기 |
| RMSE | √mean((y − ŷ)²) (오차 → 제곱 → 평균 → 제곱근) | 큰 오차에 더 민감, 단위는 정답과 동일 (ms) |

- 지표에 따라 모델 선택이 달라질 수 있습니다.

| 모델 | MAE | RMSE | 특징 |
|---|---|---|---|
| A | 20ms | 40ms | 한 건의 큰 오차 (MAE는 작지만 RMSE는 큼) |
| B | 30ms | 30ms | 고른 오차 |

- 평균만 보지 말고 **큰 잔차의 ID·실제값·예측값**을 확인합니다.
- 회귀 점수와 분류 F1을 합쳐서 평균내지 않습니다.

### 3-2. 5-Fold 교차검증 점수

- `cross_validate`의 `test_f1`/`test_score`는 **train60 내부 fold 평가 12건의 점수**이며, 보관한 test20이 아닙니다.
- 각 fold는 새 Pipeline을 만들어 학습 48건으로 fit하고, 평가 12건은 transform·predict만 합니다.
- 한 번의 CV에 여러 지표를 기록할 수 있습니다.

```python
scores = cross_validate(
    pipe, X_train, y_train, cv=CLS_FOLDS,
    scoring={"f1": "f1", "auc": "roc_auc"},   # 같은 fold에 여러 지표
    return_train_score=True,
    error_score="raise",                       # 실패를 조용히 숨기지 않음
    n_jobs=1,
)
```

- 회귀는 `scoring="neg_root_mean_squared_error"`를 쓰고, **보고할 때 부호를 되돌립니다.**
  - `rmse = -scores["test_score"]`
  - 예: neg_RMSE가 −500과 −700이면 실제 RMSE 500ms가 더 좋음

### 3-3. 점수 집계 시 주의

| 집계 방식 | 설명 |
|---|---|
| fold 평균 ± 표준편차 | 분할에 따라 결과가 흔들렸는지 보는 진단 근거 |
| OOF 예측을 합친 점수 | 각 행을 학습하지 않은 모델로 예측한 뒤 합쳐서 계산 |

- **평균 ± 표준편차를 곧바로 95% 신뢰구간이라고 쓰지 않습니다.**
- fold F1 평균과 합친 F1은 분모·비선형성 때문에 **다를 수 있습니다.**
  - 예: 같은 크기 두 fold의 RMSE가 2와 10이면 평균은 6, 합친 RMSE는 약 7.21
- 평균을 낸 대상과 가중 방식을 기록하고, 서로 다른 계산의 숫자를 같은 열에 섞지 않습니다.
- CV 평균이 조금 높다고 통계적으로 우수하다고 단정하지 않습니다. 표본 수·분산·후보 선택 과정을 함께 봅니다.

### 3-4. 자료 구조에 맞는 분할

| 자료의 구조 | 검토할 분할 | 추가 검사 |
|---|---|---|
| 독립 요청·분류 | `StratifiedKFold` | fold별 양성 수, ID 교집합 |
| 동일 고객/요청의 반복 행 | `GroupKFold` 등 그룹 분리 | 같은 그룹이 학습·평가 양쪽에 없는가 |
| 시간 순서·미래 예측 | `TimeSeriesSplit` 등 시간 분리 | 미래 자료가 과거 학습에 들어오지 않는가 |
| 선택한 최고 점수의 낙관성 | 별도 최종 test / 필요 시 nested CV | 선택용 자료와 최종 평가의 역할 구분 |

> 분할 방법은 점수가 잘 나오는지로 고르지 않고, **실제로 예측할 상황에 맞춰** 정합니다.

## 4. 특성 설계 (Feature Engineering)

원본 입력에 의미 있는 변환·조합을 만들어 예측에 필요한 정보를 표현하는 일입니다.

**진행 순서:** 가설 → 변환 정의 → 입력/출력 검사 → 고정 조건 비교 → 해석의 한계

### 4-1. 파생 변수 예시

| 특성 | 정의 | 필요한 주의 |
|---|---|---|
| `log_input_chars` | log(1 + input_chars) (`np.log1p`) | 0에서도 0, 음수 금지, NaN 유지 |
| `chars_per_slot` | input_chars / (1 + allowed_tools) | 분모 0 방지, 실제 도구당 실행시간이 아님 |

- 원본 4열은 그대로 유지하고 파생 변수는 **추가만** 합니다.
- 새 특성도 **요청 전에 계산 가능**해야 합니다. 정답·실행 결과(`elapsed_ms`, `retry_count` 등)로 만든 파생 변수는 시점 누수입니다.
- 원본을 바꾸지 않도록 `X.copy()` 후 열을 추가합니다.

### 4-2. 행별 규칙 vs 학습해야 할 통계

| 행별로 계산 가능한 규칙 | 자료에서 추정하는 변환 |
|---|---|
| `log1p(글자 수)`, 글자 수 / (1 + 도구 수) | 중앙값·평균·표준편차, 범주 목록, 특성 선택, PCA, K-Means |
| 한 행의 사전 입력만 사용 | 학습 자료 또는 **fold 학습 부분에서만 fit** |

- 행별 규칙도 Pipeline에 넣어 학습·추론의 규칙을 일치시킵니다.
- 입력만 쓰는 비지도 변환이라도 평가 자료로 fit하면 전체 모델 평가에 누수가 생길 수 있습니다.
- 정답을 이용하는 인코딩·선택은 더 엄격한 누수 방지 절차가 필요합니다.

### 4-3. Pipeline에 연결

```python
features = FunctionTransformer(add_features, validate=False)  # DataFrame 입력 유지

pipe = Pipeline([
    ("features", features),
    ("pre", make_pre(engineered=True)),
    ("model", LogisticRegression(C=1, max_iter=1000)),
])
pipe.fit(X_train, y_train)
pipe[:-1].transform(X_train).shape   # 모델 전까지의 변환만 실행 → (60, 10)
```

- 열 구성: 수치 4(원본 2 + 파생 2) + 원-핫 6 = **10열**

### 4-4. 효과는 같은 조건에서 분리해 비교

| 비교 | 기존 | 파생 추가 |
|---|---|---|
| CV F1 | 0.522 | 0.551 |
| CV 표준편차 | 0.209 | 0.190 |
| valid F1 | 0.333 | 0.182 |

- CV는 올랐지만 valid는 낮아졌습니다. **개선으로 확정하지 않고** 현재 결과와 한계를 모두 보고합니다.
- 추가했다고 항상 좋아지지 않으므로 같은 모델·같은 CV로 검증합니다.
- `return_estimator=True`로 fold별 fitted Pipeline을 받아, 대체값(`statistics_`)이 **각 fold 학습 48건의 중앙값**과 일치하는지 `np.allclose`로 검사할 수 있습니다.

## 5. K-Means 군집화

### 5-1. KNN과 K-Means

| 구분 | KNN | K-Means |
|---|---|---|
| 학습 유형 | 지도학습 | 비지도학습 |
| 사용 자료 | 입력 + 정답 | 입력만 (정답 없이 비슷한 입력을 묶음) |
| K의 의미 | 참고할 이웃 수 | 만들 군집의 개수 |
| 예측 방식 | 가까운 학습 사례의 라벨·값 사용 | 군집 중심을 학습하고 새 입력을 가까운 중심에 할당 |

> 군집 번호(0·1·2)는 **순서·크기·성공/실패 의미가 없는 이름표**입니다. 번호를 서로 바꿔도 같은 묶음입니다.

### 5-2. 알고리즘

1. **초기화**: K개의 중심을 선택 (`k-means++`)
2. **할당**: 각 점을 가장 가까운 중심에 배정
3. **갱신**: 각 군집에 속한 점들의 평균으로 중심 이동
4. **반복·종료**: 할당/중심이 안정되거나 종료 조건에 도달

- 목적은 중심까지 **제곱거리의 합(inertia)** 을 줄이는 것이며, 초기값에 따라 해가 달라질 수 있습니다.

```python
km = KMeans(n_clusters=2, n_init=10, random_state=42)
labels = km.fit_predict(X)        # y를 전달하지 않는다
print(km.cluster_centers_, km.inertia_)
```

| 설정 | 의미 |
|---|---|
| `n_clusters` | 군집 개수 |
| `n_init=10` | 여러 번 초기화해 가장 좋은 결과 선택 |
| `random_state=42` | 초기화 재현 |

### 5-3. 요청 로그에 적용

- 거리 기반이므로 **결측 대체 → 표준화 → K-Means** 순서로 Pipeline을 구성합니다. (train60의 수치 2열만 사용, 정답 `y`는 사용하지 않음)
- 중심은 결측 대체 후 좌표의 평균입니다. "실제 사용한 도구 수"나 "성공률"로 해석하지 않습니다.

### 5-4. 군집 평가

| 지표 | 의미 | 주의 |
|---|---|---|
| inertia | 각 점에서 소속 중심까지 제곱거리의 합 | K가 늘면 작아지기 쉬워 **최솟값만으로 K를 고르지 않음** |
| silhouette | 같은 군집과의 거리 vs 다른 군집과의 거리 비교 (−1~1, 높을수록 분리가 좋음) | 군집 수가 2 이상, 표본 수 미만이어야 계산 가능 |

| K | inertia | silhouette |
|---|---|---|
| 2 | 69.864 | 0.392 |
| 3 | 40.430 | **0.453** |
| 4 | 30.374 | 0.445 |

- K=3의 silhouette가 가장 높고 K=4는 inertia가 더 작습니다. 한 지표만 보고 군집 수를 늘리지 않습니다.
- 새 자료에서도 K=3이 최선이라는 뜻은 아닙니다. 분리도가 높아도 업무적으로 의미 있는 집단이라는 보장은 없습니다.

### 5-5. 새 요청은 `predict`로 할당

```python
cluster_pipe.predict(new)       # 기존 중심에 새 입력 할당
# cluster_pipe.fit_predict(new) ← 금지: 중심을 새 자료로 다시 학습함
```

> **주의:** K-Means를 예측 모델 평가와 연결되는 변환으로 쓴다면, 전체 100건이 아니라 **학습 부분에서만 fit**해야 합니다. (CV 안에 넣는 구조)

## 6. 선택 확정과 최종 평가

### 6-1. 데이터별 역할

| 데이터 | 역할 |
|---|---|
| train 60 | 5-fold CV로 후보 비교 (전처리도 fold 안에서) |
| valid 20 | 개발 중 진단용. **이미 사용했으므로 최종 독립 점수가 아님** |
| train + valid 80 | 설정 확정 후 새 Pipeline 재학습 |
| test 20 | 고정된 버전의 최종 평가 (**한 번만**, 보고 후 재선택 금지) |

### 6-2. 최종 평가 순서

1. **선택**: train60 내부 CV에서 사전에 정한 규칙(실패 클래스 CV 평균 F1 최대, 동점 규칙 포함)으로 선택
2. **동결**: 선택 모델·설정·특성 규칙·임계값(0.5)·평가 정책을 `evaluation_lock.json`에 저장
3. **재학습**: `clone`으로 학습 상태 없는 새 Pipeline을 만들어 **train+valid 80건**으로 fit
4. **최종 보고**: test20에 transform/predict만 적용하고 지표·예측·한계를 저장

- 선택 함수(`compare_candidates`, `select_name`)는 **test를 입력받지 않습니다.**
- 80건 재학습 후 중앙값이 바뀌는 것은 오류가 아닙니다. 설정 확정 뒤 허용한 개발 80건으로 새로 fit한 결과인지만 확인합니다.
- 보고 지표는 라벨 지표(Accuracy·Precision·Recall·F1)와 점수 지표(AUC)를 함께 기록합니다.

### 6-3. 이번 실습의 결과 (교육용 고정 버전)

| 모델 | CV F1 | fold 표준편차 | valid F1 |
|---|---|---|---|
| Dummy | 0.000 | 0.000 | 0.000 |
| Logistic | 0.522 | 0.209 | 0.333 |
| KNN3 | 0.336 | 0.176 | 0.545 |
| Tree | 0.542 | 0.124 | 0.333 |
| Forest | 0.280 | 0.254 | 0.222 |
| XGBoost | 0.500 | 0.123 | 0.182 |
| Logistic + 파생 2개 | **0.551** | 0.190 | 0.182 |

- 사전 규칙(CV F1 최대)에 따라 **Logistic + 파생 2개**를 선택했습니다. Tree와의 약 0.009 차이를 확실한 우월성이라고 주장하지 않습니다.
- 최종 test20: Accuracy 0.750 / Precision 0.600 / Recall 0.500 / **F1 0.545** / AUC 0.786 (TN 12, FP 2, FN 3, TP 3 → **실패 발견 3/6**)

### 6-4. 최종 점수 보고 시 한계

- 최종 test는 20건, 실제 실패는 6건뿐인 **소표본**입니다.
- 여러 후보·여러 날의 개발 조회가 있었고, 합성 데이터이므로 실제 서비스 검증이 아닙니다.
- 좋은 ROC-AUC가 운영 비용이나 확률 보정을 보장하지 않습니다.
- **CV 점수와 최종 test 점수를 같은 성능이라고 합치지 않습니다.** (지표·자료·임계값을 함께 기록)

> **test 결과를 본 뒤 모델·특성·임계값을 바꾸면** test를 선택에 사용한 것입니다. 기존 결과는 탐색 결과로 보존하고, 개발이 재개되었음을 밝힌 뒤 **새 독립 평가 자료와 계획**이 필요합니다. 반면 같은 최종 버전의 결과 파일을 재생성하는 것은 허용되는 재현 확인입니다.

## 📝 오늘의 핵심 정리

- 지표는 **분모·양성 라벨·단위**를 알고 선택하며, 같은 자료와 조건에서만 비교합니다.
- Accuracy는 불균형 자료에서 실패를 못 찾아도 높게 나올 수 있으므로, 실패(1)의 Precision·Recall·F1과 실제 건수를 함께 봅니다.
- AUC는 **점수의 순위 평가**이고, 임계값은 별도의 운영 정책입니다. 같은 AUC에서도 FP·FN이 달라질 수 있습니다.
- 회귀는 단위가 있는 RMSE·MAE를 쓰고, CV의 음수 scorer는 부호를 되돌려 보고합니다. fold 평균 ± 표준편차는 신뢰구간이 아닙니다.
- 파생 특성은 예측 시점에 계산 가능해야 하고, 통계를 학습하는 변환(파생 특성 이후의 전처리, K-Means 등)은 **학습 부분 안에서만 fit**합니다.
- K-Means는 정답 없이 입력을 묶는 비지도 방법이며, 군집 번호에 성공/실패 의미를 붙이지 않고 새 입력에는 `predict`를 씁니다.
- 선택을 확정(동결)한 뒤 개발 80건으로 재학습하고 test 20건을 한 번만 평가합니다. **test를 본 뒤의 재선택은 금지**입니다.
- 결과는 한계와 함께 보고하고, 코드·환경·근거·Git 이력으로 **다시 실행할 수 있게** 남깁니다.
