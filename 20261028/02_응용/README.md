# 응용 · 코드와 데이터·결과를 가볍게 나누기

구조는 **코드7개 + README + data/ + outputs/**입니다. 추가 사용자 정의 함수나 공용 모듈을 작성하지 않습니다. TODO는 총8곳입니다. 각 파일의 전처리 구성 코드는 제공되어 있습니다.

```text
02_응용/
├─ README.md
├─ 01_metrics.py ... 07_project.py
├─ data/
│  ├─ requests.csv
│  └─ split_manifest.csv
└─ outputs/  ← 직접 실행한 결과
```

`data/requests.csv`는 PPT와 같은 합성100건입니다. 수치·범주 결측은 전처리 학습을 위한 의도된 결측이며, 불량파일·중복ID·형식오류를 복구하는 과제는 없습니다. 입력4열은 input_chars·allowed_tools·task_type·priority입니다. failed는 분류 정답, elapsed_ms는 회귀 정답이며 status·retry_count는 실행 후 정보이므로 입력에서 제외합니다.

split_manifest.csv의 split과 position으로 **소속뿐 아니라 행 순서까지** 전날과 동일하게 읽습니다. train60·valid20·test20이며 CV는 train 안의 5-fold(학습48·평가12)입니다.

## 흐름과 사전 조건

01~05는 독립입니다. 06은 **04가 만든 feature_comparison.csv**를 읽습니다. 07은 **06이 만든 selection.json**을 읽습니다. 제출 전에는 01→02→03→04→05→06→07을 완료하세요. 08은 07을 그대로 재실행합니다.

**04의 CV_F1으로만 선택하며 valid는 진단용입니다.** 최종 후보는 Logistic·Logistic_FE 2개로 줄였습니다. PPT의 전체7후보와 저장·복원은 심화 프로젝트에서 다룹니다. 임계값0.5를 고정하고, 확률이 정확히0.5일 때는 성공0으로 판정합니다.

행별 log1p와 input_chars/(1+allowed_tools)는 자기 행 값만 사용합니다. 이 두 공식은 CV 앞에서 계산해도 다른 행 통계·정답을 보지 않습니다. 중앙값·표준화·범주 목록은 Pipeline이 각 fold 학습 부분에서 배웁니다.
