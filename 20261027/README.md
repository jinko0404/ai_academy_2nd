## 1. 결정트리 (Decision Tree)

질문을 이어가며 데이터를 나누고, 도착한 잎(leaf)의 값으로 예측하는 모델입니다.

| 구성 요소 | 역할 |
|---|---|
| 루트 노드 | 첫 번째 질문 |
| 내부 노드 | 이어지는 질문 (한 번에 한 특성의 조건을 검사) |
| 잎 (Leaf) | 최종 예측이 이루어지는 위치 |

| 문제 유형 | 잎의 예측 방식 |
|---|---|
| 분류 트리 (`DecisionTreeClassifier`) | 잎의 클래스 분포(확률)로 예측 |
| 회귀 트리 (`DecisionTreeRegressor`) | 잎에 속한 정답의 평균으로 예측 |

- **질문(분할 기준)은 사람이 적는 것이 아니라 학습 데이터에서 자동으로 선택됩니다.** (`fit`: 좋은 질문 탐색 / `predict`: 찾은 질문을 따라 잎으로 이동)
- **Gini 불순도**: 노드에 클래스가 얼마나 섞여 있는지 나타냅니다. 분할 후 불순도가 가장 많이 줄어드는 질문을 선택합니다.
  - 예: 성공 3건·실패 3건이면 Gini = 1 − 0.5² − 0.5² = 0.5
- 회귀 트리는 **학습 범위 밖의 값을 외삽하지 않습니다.** 범위 밖 입력은 가장 가까운 잎의 평균을 그대로 예측합니다.

> **주의:** Gini는 분류 노드의 혼합 정도를 나타내는 값이며, 회귀 오차나 시험 점수 같은 평가 지표가 아닙니다.

## 2. 과적합과 복잡도 제어

트리가 깊어질수록 학습 데이터의 작은 차이와 잡음까지 나누게 되어 과적합이 발생할 수 있습니다.

| 설정 | 의미 | 주의점 |
|---|---|---|
| `max_depth` | 최대 질문 깊이 제한 | 너무 작으면 필요한 규칙도 못 배움 (과소적합) |
| `min_samples_leaf` | 각 잎의 최소 학습 행 수 | 값을 키우면 작은 조각으로 나누는 것을 억제 |
| `min_samples_split` | 노드를 더 나눌 최소 학습 행 수 | 자식 잎의 크기 조건과는 다름 |
| `ccp_alpha` | 복잡도 비용을 고려한 사후 가지치기 | 클수록 더 단순한 트리를 선호 |

**과적합 진단:** 같은 분할과 같은 지표로 train 점수와 valid 점수를 함께 비교합니다.

| 상태 | train | valid |
|---|---|---|
| 과적합 | 높음 (예: F1 1.000) | 크게 낮음 (예: F1 0.500) |
| 과소적합 | 낮음 | 낮음 |

> **주의:**
> - train 점수가 1.0이라고 해서 모델 선택을 끝내면 안 됩니다.
> - train–valid 차이는 단서일 뿐이며, 표본이 작다는 점과 데이터 분포 차이도 함께 살펴야 합니다.
> - valid 점수를 올리려고 틀린 행을 지우는 것은 평가 자료를 결과에 맞춰 바꾸는 부당한 비교입니다.

## 3. Random Forest

여러 개의 트리를 **독립적으로** 만들어 결과를 결합하는 앙상블(배깅) 모델입니다.

### 3-1. 동작 방식

1. train 데이터에서 **중복을 허용하여** 각 트리가 학습할 데이터를 추출
2. 각 트리는 **분할할 때마다 일부 특성만 후보로 선택**
3. 여러 트리의 결과를 결합

| 문제 유형 | 결합 방식 |
|---|---|
| 분류 | 트리별 클래스 **확률을 평균**한 뒤 클래스 결정 |
| 회귀 | 트리별 예측값의 **평균** |

- 핵심은 같은 실수를 반복하는 트리가 아니라 **서로 다른 관점을 가진 트리**를 묶는 것입니다.
- sklearn은 확률을 평균하기 때문에 개별 트리의 클래스 다수결과 결과가 다를 수 있습니다.

### 3-2. 주요 하이퍼파라미터

| 설정 | 의미 |
|---|---|
| `n_estimators` | 숲에 포함할 **트리의 개수** (트리 깊이가 아님) |
| `max_depth` | 개별 트리의 최대 깊이 |
| `min_samples_leaf` | 각 잎의 최소 학습 행 수 |
| `max_features` | 분할마다 살펴볼 특성 후보의 수·비율 (분류 `sqrt`, 회귀 `1.0`) |
| `random_state` | 난수 재현성 확보 |

> **주의:** 앙상블이라고 해서 항상 단일 트리보다 검증 점수가 높은 것은 아닙니다. 모델 이름이나 트리 수가 아니라 **같은 평가 조건에서의 결과와 오류**로 판단합니다.

## 4. 특성 중요도

모델이 예측에 어떤 입력을 더 많이 사용했는지 살펴보는 진단 방법입니다.

| 구분 | MDI (불순도 기반) | 순열 중요도 (Permutation) |
|---|---|---|
| 계산 방식 | 분할에서 줄어든 불순도를 특성별로 합산하고 트리 전체에서 평균 | 한 열의 값을 섞은 뒤 점수가 얼마나 떨어지는지 측정 |
| 사용 도구 | `feature_importances_` | `permutation_importance` |
| 기준 데이터 | 학습 데이터 | 평가 데이터 (예: valid) |
| 재학습 | 해당 없음 | **하지 않음** (학습된 모델을 고정) |
| 특징 | 합이 1, 학습 분할에 대한 기여 | 점수 감소량이며 **음수도 나올 수 있음** |

- One-hot 인코딩 후에는 열이 늘어나므로 `get_feature_names_out()`으로 **열 이름과 중요도의 순서를 맞춰** 확인합니다.
- 순열 중요도에서 원본 범주 열을 섞으면 해당 더미 열 묶음이 함께 평가됩니다.

### 해석 시 피해야 할 결론

- 값의 종류가 많은 특성은 분할 후보가 많아 MDI가 **높게 보일 수 있습니다.**
- 상관된 특성끼리는 정보가 중복되어 중요도가 **나뉠 수 있습니다.**
- 중요도는 **영향의 방향(양·음)이나 인과관계를 알려 주지 않습니다.** 중요도 1위 ≠ 실패의 원인
- 순열 중요도가 음수여도 바로 열을 삭제하지 않습니다. 표본 크기, 반복 변동, 모델 성능 수준, 특성 간 상관을 먼저 살핍니다.
- 중요도를 본 뒤 평가 데이터에 맞춰 열을 반복 삭제하면 **선택 편향**이 커집니다. 열 선택이 필요하면 학습 fold 안에서 수행합니다.

> 모델 성능 자체가 낮다면(예: valid F1 0.222) 그 모델의 중요도를 업무 우선순위로 단정하지 않습니다.

## 5. XGBoost와 부스팅

현재 예측이 부족한 부분을 **다음 트리가 보정**하면서 트리를 순차적으로 추가하는 방식입니다.

### 5-1. 부스팅의 원리

1. **처음 예측**: 간단한 출발점에서 시작 (예: 정답의 평균)
2. **보정 트리**: 현재 손실을 줄이는 방향을 학습
3. **예측 갱신**: `이전 예측 + 학습률 × 보정값`, 이를 순차적으로 반복

> "잔차를 배운다"는 설명은 **제곱오차 기준의 직관**입니다. 분류에서는 손실의 기울기 정보를 사용합니다.

### 5-2. Random Forest와 비교

| 관점 | Random Forest (배깅) | XGBoost (부스팅) |
|---|---|---|
| 학습 관계 | 트리를 **독립적**으로 구성 | 이전 예측을 보정하며 **순차적**으로 추가 |
| 다양성 | 표본과 특성 후보의 무작위성 | 손실의 기울기·곡률에 따른 보정 |
| 예측 결합 | 확률 또는 수치의 평균 | 기본 점수에 보정값을 누적 |
| 핵심 조절 | 트리 수, 깊이, 잎 크기, 특성 수 | 깊이, 학습률, 회차, 표본·특성 비율 |

### 5-3. 주요 하이퍼파라미터

| 설정 | 의미 |
|---|---|
| `n_estimators` | 보정 트리를 추가하는 회차 |
| `learning_rate` | 한 회차의 보정을 얼마나 반영할지 |
| `max_depth` | 각 보정 트리의 최대 깊이 |
| `min_child_weight` | 자식 노드에 필요한 Hessian 합의 하한 (`min_samples_leaf`와 다름) |
| `subsample` / `colsample_bytree` | 행 / 트리별 특성의 사용 비율 |
| `reg_lambda` | 잎 가중치에 대한 L2 규제 |
| `objective` | 목적함수 (`binary:logistic` 이진 분류, `reg:squarederror` 회귀) |
| `eval_metric` | 학습 진단용 지표 (`logloss`, `rmse` 등) |

> **주의:**
> - 학습률을 낮추거나 규제를 강화한다고 항상 성능이 좋아지지는 않습니다. 회차·복잡도와 함께 비교합니다.
> - `logloss`(학습 진단용 손실)와 `F1`(최종 선택 지표)은 서로 다른 역할입니다.
> - `min_child_weight`는 "자식 노드의 최소 행 수"가 아닙니다.

### 5-4. 조기 종료 (Early Stopping)

손실 개선이 멈추는 시점에서 학습을 종료하는 방법입니다. 이때 사용하는 **stop 데이터도 모델 선택에 사용되므로**, 보관 중인 valid·test를 넣지 않고 train 내부에서 분리해 사용합니다.

## 6. 교차검증 (Cross-Validation)

한 번의 검증 분할에 의존하지 않기 위해, **train 데이터 안에서** 학습과 평가를 여러 번 반복하는 방법입니다.

### 6-1. 5-Fold 방식 (train 60건 기준)

| 회차 | 학습 | 평가 |
|---|---|---|
| 1 ~ 5 | 48건 | 12건 (회차마다 다른 12건) |

각 회차에서 `전처리 fit(48) → 모델 fit(48) → transform·predict(12)` 순서로 진행하고, fold별 점수·평균·표준편차를 비교합니다.

### 6-2. 분할기 선택

| 상황 | 분할기 | 비고 |
|---|---|---|
| 분류 (독립 요청) | `StratifiedKFold` | 클래스 비율을 유지 |
| 회귀 (독립 요청) | `KFold` | 연속값 정답은 stratify하지 않음 |
| 같은 요청이 여러 행 | 그룹 단위 분할 | 같은 ID가 학습·평가에 섞이지 않게 |
| 미래 예측 | 시간 순서 분할 | 미래 정보가 학습에 들어가지 않게 |

### 6-3. 데이터 누수 방지

| 잘못된 순서 | 올바른 순서 |
|---|---|
| train 전체에 전처리를 `fit`한 뒤 변환된 배열을 fold로 나눔 | **아직 fit하지 않은 Pipeline 전체**를 `cross_validate`에 전달 |
| 평가 fold의 통계가 학습 전처리에 포함됨 (누수) | 각 fold의 학습 데이터에서만 전처리와 모델을 fit |

```python
cv_result = cross_validate(
    model,                  # 전처리 + 모델이 묶인 Pipeline (fit 전)
    X_train, y_train,
    cv=cv,                  # StratifiedKFold 또는 KFold
    scoring="f1",
    return_train_score=True,
)
```

### 6-4. 결과 해석 시 주의

- `cross_validate`의 `test_score`는 "fold 평가 점수"라는 **반환 이름**일 뿐이며, 보관한 test 데이터가 아닙니다.
- **평균 ± 표준편차는 95% 신뢰구간이 아닙니다.** fold 결과의 산포를 기록한 값입니다.
- fold의 평가 데이터가 12건뿐이면 점수가 구성에 따라 크게 달라집니다. (예: fold별 F1이 0.000 ~ 0.667)
- 회귀의 `neg_root_mean_squared_error`는 큰 값이 좋도록 **음수로 반환**되므로, 부호를 되돌려서 RMSE로 해석합니다.
- CV도 모델 선택에 사용한 결과이므로, 평균이 높다는 사실만으로 최종 성능을 확정하지 않습니다.

## 7. 모델 비교 시 주의할 점

- **후보 모델, 지표, 분할을 사전에 정한 뒤 비교합니다.** CV나 valid를 반복 조회해도 선택 편향은 사라지지 않습니다.
- 동일한 문제의 후보들은 **같은 fold 인덱스**로 비교합니다.
- 분류(F1)와 회귀(RMSE)의 지표는 합산하거나 직접 비교하지 않습니다.
- 모델별 전처리를 다르게 구성하더라도(예: KNN은 표준화, 트리 계열은 스케일링 없음) **학습 절차 전체**를 비교합니다.
- 점수 차이가 매우 작으면 우열로 단정하지 않고 **추가 검증 대상**으로 기록합니다. 동점이면 더 단순한 모델을 우선합니다.
- **CV 기준 최고 모델과 valid 기준 최고 모델이 다를 수 있습니다.** 유리한 결과만 골라 보고하지 않고 모두 기록합니다.
- 판단 기준이 바뀌었다면(예: valid 기준 → CV 기준) 그 사실도 보고서에 남깁니다.

> 오늘의 최고 점수는 실험 결과일 뿐, 서비스 배포를 승인하는 성능 인증이 아닙니다.

| 최종 평가 | 선택이 끝날 때까지 test 데이터는 보관 |

> - 새로운 범주가 들어와도 기존 열 구성(예: 8열)이 유지되어야 하고, 필수 열이 없으면 임의로 채우지 않고 **명확한 오류**를 내야 합니다.
> - `joblib.load`는 **직접 만든 신뢰할 수 있는 파일만** 불러옵니다. 저장 시 라이브러리 버전과 입력 스키마도 함께 기록합니다.
> - 오류 없이 끝났다는 것과 요구사항대로 동작했다는 것은 다릅니다.

## 📝 오늘의 핵심 정리

- 결정트리는 질문을 이어가며 데이터를 나누고, 잎의 값(분류: 클래스 분포 / 회귀: 평균)으로 예측합니다.
- 트리가 깊을수록 과적합 위험이 커지므로 `max_depth`, `min_samples_leaf` 등으로 복잡도를 제어하고 train/valid를 함께 확인합니다.
- Random Forest는 독립적인 트리를 결합(확률 평균)하고, XGBoost는 이전 예측의 부족한 부분을 순차적으로 보정합니다.
- 앙상블이 항상 단일 모델보다 좋은 것은 아니므로 같은 조건에서 비교합니다.
- 특성 중요도(MDI·순열)는 모델의 의존성을 진단할 뿐, **인과관계가 아닙니다.**
- 교차검증은 train 내부에서 수행하며, 전처리까지 **각 fold의 학습 데이터 안에서** fit해야 누수가 없습니다.
- CV 평균·표준편차는 신뢰구간이 아니며, valid와 순위가 다를 수 있으므로 결과를 함께 기록합니다.
- test 데이터는 선택이 끝날 때까지 보관하고, 비교표·fold 점수·중요도·재현성 기록까지 남깁니다.
