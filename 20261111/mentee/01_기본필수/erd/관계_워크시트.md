# 두 테이블 관계 워크시트

```text
+--------------------+          +--------------------+
| categories         |          | knowledge          |
+--------------------+          +--------------------+
| id          [PK]   | 1      N | id          [PK]   |
| name               |----------| title              |
+--------------------+          | content            |
                                | category_id [FK]   |
                                +--------------------+

FK reference: knowledge.category_id -> categories.id
```

1. 각 표의 PK: categories.id, knowledge.id
2. FK의 출발 열 → 대상 열: knowledge.category_id → categories.id
3. 분류 한 개에는 지식이 몇 개까지 연결될 수 있는가? 0개 이상의 여러 지식이 연결될 수 있다. 여러 knowledge 행이 같은 categories.id를 참조할 수 있으므로 분류와 지식은 1:N 관계다.
4. 지식 한 개는 분류 몇 개를 참조하는가? 1개만 연결될 수 있다. 한개의 knowledge행은 한개의 categories.id를 참조할 수 있으므로 분류와 지식은 1:N 관계다.
5. 지식이 있는 분류를 삭제하면? ON DELETE RESTRICT 제약이 걸려 있으므로 삭제가 거부되며 값은 그대로 유지가 된다.
6. 제목 중복은 허용되는가? title에는 UNIQUE 제약이 없으므로 제목 중복은 허용된다.
7. IDENTITY와 PK의 역할은 어떻게 다른가? PK는 해당 열 값의 NULL을 금지하고, 유일성을 보장해주는 기능이 있으며, IDENTITY는 값을 생략할 시 다음 값을 자동으로 채워주는 값으로 PK와는 다르게 유일성을 보장하지 않는다.

그림과 실제 제약조건은 별개입니다. 공통 준비 SQL과 실제 pg_constraint 결과를 대조합니다.
