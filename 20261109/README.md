# Day 16 기본 개념과 용어 정리

문서 이미지에서 글자와 위치를 읽고, 필요한 값을 구조화한 뒤, 답변의 근거를 원문에서 확인하는 과정이다. 영수증이라면 합계 금액과 함께 그 금액이 표시된 페이지와 위치도 기록한다.

## 1. OCR과 이미지 전처리

**OCR(Optical Character Recognition, 광학 문자 인식)**은 이미지 속 글자를 텍스트로 바꾸는 기술이다. 보통 **이미지 보정 → 글자 영역 탐지 → 문자 인식 → 읽기 순서 정리** 순으로 처리한다.

| 용어 | 뜻 |
| --- | --- |
| 그레이스케일(Gray) | 색상 대신 밝기만 남긴 이미지. |
| 이진화(Thresholding) | 밝기 기준으로 픽셀을 두 값으로 나눠 글자와 배경을 구분하는 작업. |
| 기울기·원근 보정 | 비스듬히 놓이거나 사다리꼴로 찍힌 문서를 펴서 글줄을 읽기 쉽게 만드는 작업. |
| Crop | 한 줄, 금액, 표처럼 필요한 이미지 영역만 잘라낸 것. |
| PSM(Page Segmentation Mode) | Tesseract에서 입력을 전체 페이지, 텍스트 블록, 한 줄, 한 단어 등 어떤 구조로 해석할지 정하는 설정. |
| Bounding box(bbox) | 인식한 단어나 줄을 둘러싼 사각형의 좌표. 크롭·리사이즈한 이미지의 위치를 원본에 표시하려면 좌표를 변환한다. |
| Confidence | OCR 엔진이 인식 결과에 매긴 신뢰도 점수. 점수가 높아도 원문과 다를 수 있다. |

## 2. 정보 추출과 구조화

**구조화**는 OCR 문자열에서 날짜·문서번호·금액처럼 필요한 항목을 찾아 정해진 형식으로 저장하는 작업이다. 합계가 **1,234,500원**이라면 **raw**에는 원문을, **value**에는 계산용 숫자 **1234500**을 저장한다. 페이지와 bbox를 함께 남기면 원문에서 값을 다시 확인할 수 있다.

| 용어 | 뜻 |
| --- | --- |
| 정규화(Normalization) | 날짜, 숫자, 공백 등의 표기를 일정한 형식으로 통일하는 작업. |
| 정규표현식(Regex) | 날짜나 금액처럼 일정한 패턴을 가진 문자열을 찾는 규칙. |
| 필드(Field) | 합계 금액이나 발행일처럼 문서에서 추출할 개별 항목. |
| Key-value 추출 | ‘합계’ 같은 라벨과 그에 대응하는 값 및 근거를 연결하는 작업. |
| 표 구조 복원 | 추출한 글자를 원래 표의 행·열·셀에 배치하고 머리글과 값의 관계를 되살리는 작업. |
| JSON과 스키마(Schema) | JSON은 데이터를 표현하는 형식이다. 스키마는 필요한 항목과 값의 자료형을 정의한다. |
| 업무 규칙 검증 | 필수 항목과 값의 관계를 확인하는 작업. 예를 들어 합계가 공급가와 세금의 합인지 검사한다. |

## 3. VLM과 문서 질의응답

**VLM(Vision-Language Model, 시각·언어 모델)**은 이미지와 텍스트를 함께 처리하는 모델이다. OCR로 영수증의 글자와 위치를 읽고, VLM으로 ‘이 영수증의 최종 결제 금액은 얼마야?’ 같은 질문에 답할 수 있다.

| 용어 | 뜻 |
| --- | --- |
| Processor | 이미지와 질문을 모델 입력 형식으로 변환하는 구성 요소. |
| Vision Encoder | 이미지에서 모델이 사용할 시각 특징을 추출하는 구성 요소. |
| Projector | 시각 특징을 언어 모델이 사용할 수 있는 표현으로 연결하는 모듈. |
| LLM(Large Language Model) | 질문과 시각 특징을 바탕으로 텍스트 답변을 생성하는 언어 모델. |
| Grounding(근거 연결) | 답변을 실제 문서의 원문·페이지·이미지 영역과 연결하는 작업. |
| Hybrid(혼합 방식) | OCR 결과와 원본 이미지 또는 크롭을 함께 활용해 VLM 답변을 생성하거나 검증하는 방식. |

VLM이 답변과 함께 제공한 인용문과 좌표는 원본과 대조한다. 근거가 부족하면 값을 `null`로 두고 검토 사유를 기록한다.

## 4. 품질 평가

| 지표 | 뜻 |
| --- | --- |
| CER(Character Error Rate) | 문자 단위 치환·삭제·삽입 횟수를 정답 문자 수로 나눈 값. |
| WER(Word Error Rate) | 단어 단위 치환·삭제·삽입 횟수를 정답 단어 수로 나눈 값. |
| 필드 정확도(Field accuracy) | 대상 필드 중 날짜·금액 등의 값이 정확히 추출된 비율. |
| 근거 일치 | 답변이 가리키는 문자열이나 이미지 영역이 실제로 답을 뒷받침하는지 확인하는 기준. |
| 지연 시간(Latency) | 한 건을 처리하는 데 걸리는 시간. 모델 추론 시간과 전처리·후처리를 포함한 전체 시간을 구분한다. |
| 처리량(Throughput) | 초당 처리하는 페이지·이미지·프레임 수. |

OCR과 VLM을 비교할 때는 같은 문서와 정답, 같은 정규화 기준을 사용한다. JSON 형식 검증과 실제 값의 정확도는 별도로 평가한다.

## 5. 엣지 배포와 영상 처리

| 용어 | 역할 |
| --- | --- |
| 엣지 배포(Edge deployment) | 카메라 등 데이터가 발생하는 현장 가까이에서 모델을 실행하는 방식. |
| ONNX | 모델의 연산 그래프를 서로 다른 도구 사이에서 교환하는 형식. |
| TensorRT | 지원하는 모델을 NVIDIA GPU에서 효율적으로 실행하도록 최적화하는 추론 SDK. |
| Engine | TensorRT가 빌드한 최적화된 실행 산출물. 실행 환경의 GPU와 소프트웨어 버전 호환성을 확인한다. |
| Build / Runtime | Build는 모델을 최적화해 엔진을 만드는 단계이고, Runtime은 엔진을 불러 추론하는 단계다. |
| Jetson / JetPack | Jetson은 현장 추론에 쓰는 NVIDIA 장치 계열이고, JetPack은 Jetson용 개발·실행 소프트웨어 묶음이다. |
| DeepStream | 영상 입력, 디코딩, 배치, 추론, 추적, 출력을 연결하는 NVIDIA 영상 분석 SDK. |
| FP32·FP16·INT8 | 추론 연산에 쓰이는 수치 표현 형식. 형식을 바꿀 때는 속도·메모리와 함께 정확도를 비교한다. |

배포 흐름은 **모델 → ONNX → TensorRT 엔진 빌드 → 대상 GPU·Jetson에서 실행 및 측정**으로 이어진다.
