# Day 20 — 생성형 AI·LLM·RAG 쉬운 용어 정리

> **기준 자료:** `Day20_20261113.md` (2026-11-13 수업)

## 0. 오늘 수업을 한눈에 보기

**사용자 문장 → Tokenizer → Token ID → Embedding → Transformer(Attention·FFN) → Logits → 토큰 선택(Decoding) → 답변**

예를 들어 사용자가 **“서버 연결이 왜 안 돼?”**라고 묻는다면:

1. **Tokenizer:** 문장을 모델이 처리할 작은 조각(Token)으로 나눈다.
2. **Token ID:** 조각마다 정해진 숫자 번호를 붙인다.
3. **Embedding:** 번호를 계산에 사용할 수 있는 숫자 묶음(벡터)으로 바꾼다.
4. **Transformer:** 각 조각이 다른 조각과 어떻게 연결되는지 계산한다.
5. **Logits:** 다음에 나올 토큰 후보들에 점수를 매긴다.
6. **Decoding:** 후보 중 다음 토큰을 선택하고 반복해서 답변을 만든다.

**중요:** 자연스러운 답변을 만든다고 반드시 사실이 맞는 것은 아니다.

## 1교시 — AI·생성형 AI·LLM 생태계

### 1. AI (Artificial Intelligence, 인공지능)
- **한 줄 뜻:** 사람이 하던 지능적인 작업을 컴퓨터가 수행하도록 하는 기술 전체.
- **쉽게:** 사진에서 물체를 찾거나, 음성을 알아듣거나, 글을 분류하는 기술까지 포함하는 큰 범주.
- **기억:** AI가 가장 넓은 개념이다.

### 2. Generative AI (생성형 AI)
- **한 줄 뜻:** 배운 패턴을 바탕으로 새로운 글·이미지·음성 등을 만들어 내는 AI.
- **쉽게:** 사진에 고양이가 있는지 *판별*하는 것과, 고양이 그림을 새로 *만드는* 것은 다르다. 후자가 생성형 AI의 예다.

### 3. Foundation Model (기반 모델)
- **한 줄 뜻:** 대규모 데이터로 먼저 학습해 여러 종류의 작업에 활용할 수 있는 모델.
- **쉽게:** 한 가지 문제만 푸는 전용 기계가 아니라, 여러 작업에 응용할 수 있도록 기초를 배운 모델.

### 4. LLM (Large Language Model, 대규모 언어 모델)
- **한 줄 뜻:** 대량의 언어 데이터를 학습해 글을 이해하는 데 활용하고, 다음 토큰을 예측하며 글을 생성하는 모델.
- **쉽게:** 문장 앞부분을 보고 다음에 어떤 말이 이어질지 계산하는 일을 매우 복잡하고 정교하게 수행한다.
- **예시:** 질문 답변, 요약, 문서 분류, 코드 초안 작성.
- **주의:** LLM은 데이터베이스처럼 사실을 그대로 조회하는 장치가 아니다.

### 5. Model (모델)
- **한 줄 뜻:** 입력을 받아 계산한 결과를 내는 학습된 구조와 가중치.
- **쉽게:** 이미 공부를 마친 계산 엔진.

### 6. Runtime (실행 환경)
- **한 줄 뜻:** 모델을 컴퓨터에서 실제로 돌리는 소프트웨어·실행 체계.
- **쉽게:** 모델이 ‘요리법’이라면 Runtime은 그 요리를 실제로 수행하는 주방 환경에 가깝다.
- **수업 연결:** PyTorch, 추론 엔진.

### 7. API (Application Programming Interface)
- **한 줄 뜻:** 프로그램끼리 정해진 방식으로 요청하고 결과를 주고받는 연결 창구.
- **쉽게:** 앱이 “이 질문에 답해 줘”라고 서버에 요청하는 통로.
- **수업 연결:** FastAPI는 요청·응답을 처리하는 서비스 쪽 역할을 한다.

### 8. Hallucination (환각)
- **한 줄 뜻:** AI가 틀리거나 근거 없는 내용을 그럴듯하게 말하는 현상.
- **쉽게:** 모르는 내용을 아는 것처럼 답하는 상황.
- **기억:** 문장이 자연스럽다는 것과 내용이 정확하다는 것은 다르다.

## 2교시 — Tokenizer·Token ID·Context Window

### 9. Token (토큰)
- **한 줄 뜻:** 모델이 텍스트를 처리할 때 사용하는 조각 단위.
- **쉽게:** 문장을 레고 블록처럼 작은 부분으로 나눈 것.
- **주의:** 토큰 하나가 반드시 단어 하나인 것은 아니다. 모델마다 나누는 방식도 다르다.

### 10. Tokenizer (토크나이저)
- **한 줄 뜻:** 텍스트를 토큰으로 나누고 토큰 번호로 바꾸는 도구.
- **쉽게:** 문장을 모델용 조각으로 자르는 절단기이자 번호표 발급기.

### 11. Tokenization (토큰화)
- **한 줄 뜻:** 텍스트를 토큰으로 나누는 과정.
- **쉽게:** Tokenizer가 실제로 하는 작업 이름.

### 12. Vocabulary (어휘 집합)
- **한 줄 뜻:** 모델의 토크나이저가 사용하는 토큰과 번호의 목록.
- **쉽게:** 토큰별로 번호가 정리된 사전.

### 13. Token ID (토큰 ID)
- **한 줄 뜻:** Vocabulary에서 각 토큰에 대응하는 정수 번호.
- **쉽게:** 도서관 책의 등록번호처럼 토큰을 가리키는 번호.
- **주의:** ID가 900이라고 ID가 100인 토큰보다 의미가 크거나 중요한 것은 아니다.

### 14. Special Token (특수 토큰)
- **한 줄 뜻:** 일반 글자 대신 시작·종료·구분 등의 특별한 역할을 나타내는 토큰.
- **대표 예:** BOS(시작), EOS(종료), PAD(길이 맞춤), 대화 역할 구분용 토큰.
- **주의:** 사용 여부와 표기는 모델마다 다르다.

### 15. BOS / EOS
- **BOS (Beginning of Sequence):** 입력 또는 시퀀스의 시작을 나타내는 토큰.
- **EOS (End of Sequence):** 시퀀스의 끝을 나타내는 토큰.
- **쉽게:** 문장의 ‘시작 표지판’과 ‘끝 표지판’.

### 16. Batch (배치)
- **한 줄 뜻:** 여러 입력을 한 묶음으로 처리하는 단위.
- **쉽게:** 문장 하나씩 처리하는 대신 여러 문장을 한 번에 계산하는 것.

### 17. Padding (패딩)
- **한 줄 뜻:** 길이가 다른 입력을 함께 처리하려고 짧은 입력에 빈자리를 채우는 것.
- **쉽게:** 길이가 다른 줄을 표에 맞추기 위해 빈칸을 넣는 것.
- **주의:** 빈칸은 실제 문장 내용이 아니다.

### 18. Truncation (잘라내기)
- **한 줄 뜻:** 길이 제한을 넘는 입력 토큰을 잘라내는 것.
- **쉽게:** 글이 너무 길면 일부를 버리는 것.
- **주의:** 요약하는 것이 아니라 잘라내므로 정보가 사라질 수 있다.

### 19. Attention Mask (어텐션 마스크)
- **한 줄 뜻:** 모델이 어느 위치를 참고할 수 있는지 표시하는 정보.
- **쉽게:** ‘여기는 읽고, 여기는 무시해’라는 표시.
- **수업 예:** 토크나이저의 `attention_mask`는 실제 토큰과 패딩을 구별하는 데 사용한다.

### 20. Context (문맥)
- **한 줄 뜻:** 현재 입력을 해석하거나 다음 토큰을 예측할 때 참고하는 정보.
- **쉽게:** 질문만이 아니라 앞의 대화, 지시, 검색 문서 등을 함께 고려하는 것.

### 21. Context Window (문맥 창)
- **한 줄 뜻:** 모델이 한 번의 처리에서 참조할 수 있는 토큰 범위.
- **쉽게:** 모델이 펼쳐 놓고 읽을 수 있는 책상의 크기.
- **주의:** 영구 기억이 아니다. 입력과 출력에 사용할 토큰 예산을 함께 고려해야 한다.

### 22. Token Budget (토큰 예산)
- **한 줄 뜻:** 제한된 문맥 범위 안에서 지시·질문·검색 자료·출력에 배분할 토큰 수.
- **쉽게:** 가방 크기가 정해져 있으니 어떤 짐을 얼마나 넣을지 정하는 것.

## 3교시 — Embedding·Vector·유사도

### 23. Embedding (임베딩)
- **한 줄 뜻:** 토큰이나 문장을 계산에 사용할 수 있는 숫자 벡터로 표현하는 방법.
- **쉽게:** 글을 컴퓨터가 계산할 수 있는 숫자 좌표로 바꾸는 것.
- **예시:** `[0.2, -0.5, 0.9]`처럼 여러 숫자로 표현한다(숫자는 설명용).

### 24. Vector (벡터)
- **한 줄 뜻:** 숫자 여러 개를 순서대로 묶은 표현.
- **쉽게:** `[1, 2, 3]` 같은 숫자 묶음.

### 25. Dimension (차원)
- **한 줄 뜻:** 벡터를 이루는 숫자의 개수.
- **예시:** `[1, 2, 3]`은 3차원 벡터.

### 26. Token Embedding (토큰 임베딩)
- **한 줄 뜻:** 개별 토큰을 나타내는 벡터.
- **쉽게:** 토큰마다 계산용 숫자 묶음을 준비하는 것.

### 27. Sentence Embedding (문장 임베딩)
- **한 줄 뜻:** 문장 전체를 하나의 벡터로 나타낸 것.
- **쉽게:** 문장 하나를 검색·비교할 수 있는 숫자 좌표 하나로 요약한 것.
- **활용:** 의미가 비슷한 문장 검색.
- **주의:** 토큰 벡터를 무조건 평균하면 좋은 문장 임베딩이 되는 것은 아니다.

### 28. Embedding Table (임베딩 테이블)
- **한 줄 뜻:** 토큰 ID별로 대응하는 임베딩 벡터를 저장한 학습된 표.
- **쉽게:** 번호를 찾으면 그 번호의 숫자 묶음을 꺼내는 표.

### 29. Cosine Similarity (코사인 유사도)
- **한 줄 뜻:** 두 벡터의 방향이 얼마나 비슷한지 나타내는 값.
- **쉽게:** 두 화살표가 같은 방향을 가리키는지 비교한다.
- **값의 의미:** `1`은 같은 방향, `0`은 직교, `-1`은 반대 방향.
- **주의:** 유사도가 높다고 문서 내용이 사실이거나 답변이 정답인 것은 아니다.

### 30. Position / Positional Information (위치 정보)
- **한 줄 뜻:** 토큰이 문장 안에서 어디에 있는지 모델 계산에 반영하는 정보.
- **쉽게:** 같은 단어라도 순서가 달라지면 문장의 뜻이 달라질 수 있으니 위치를 알려주는 것.

### 31. Tensor (텐서)
- **한 줄 뜻:** 숫자를 여러 차원으로 담은 자료 구조.
- **쉽게:** 숫자 하나, 숫자 목록, 숫자 표, 숫자 표 여러 개까지 확장한 것.
- **수업 예:** `(2, 5, 8)`은 배치 2개 × 토큰 5개 × 특징 8개.

### 32. Shape (형상)
- **한 줄 뜻:** 텐서의 각 차원 크기.
- **쉽게:** 데이터가 몇 묶음이고, 한 묶음에 몇 개가 있는지 보여주는 크기표.
- **수업 기호:** `B=Batch`, `T=Token 길이`, `D=벡터 차원`.

## 4교시 — Transformer의 구조

### 33. Transformer (트랜스포머)
- **한 줄 뜻:** Attention과 FFN 등으로 구성된 블록을 반복해 문맥을 계산하는 신경망 구조.
- **쉽게:** 단어끼리 관계를 살피고 각 단어의 정보를 가공하는 여러 층의 처리 장치.
- **기억:** Attention 하나만으로 Transformer 전체가 되는 것은 아니다.

### 34. Transformer Block (트랜스포머 블록)
- **한 줄 뜻:** Transformer 안에서 반복되는 계산 단위.
- **구성:** Attention, FFN, Residual, Normalization 등.
- **쉽게:** 같은 종류의 가공 공정을 여러 층 쌓은 것.

### 35. Self-Attention (셀프 어텐션)
- **한 줄 뜻:** 한 입력 안의 토큰들이 서로의 정보를 얼마나 참고할지 계산하는 방법.
- **쉽게:** 문장 속 각 단어가 다른 단어들을 살펴보며 자기 의미를 더 잘 파악하는 과정.

### 36. FFN (Feed-Forward Network, 피드포워드 신경망)
- **한 줄 뜻:** Attention 이후 각 토큰의 벡터를 비선형적으로 변환하는 계산 부분.
- **쉽게:** 토큰끼리 정보를 주고받은 다음, 각 토큰의 정보를 한 번 더 가공하는 기계.
- **차이:** Attention은 **토큰 사이의 정보**를 섞고, FFN은 **각 토큰의 표현**을 바꾼다.

### 37. Residual Connection (잔차 연결)
- **한 줄 뜻:** 계산 결과에 기존 입력을 더해 전달하는 연결.
- **쉽게:** 새로 가공한 정보에 원래 정보를 함께 실어 보내는 우회로.
- **형태:** `x + f(x)`.

### 38. LayerNorm (Layer Normalization, 층 정규화)
- **한 줄 뜻:** 신경망 내부의 숫자 표현을 정규화해 학습을 안정시키는 방법.
- **쉽게:** 계산 결과의 숫자 규모를 정돈하는 장치.

### 39. Encoder (인코더)
- **한 줄 뜻:** 입력을 문맥에 맞는 표현으로 변환하는 구조.
- **쉽게:** 주어진 글을 읽고 그 내용을 표현하는 데 집중하는 부분.
- **수업 비교:** 대체로 양방향 문맥을 활용한다.

### 40. Decoder (디코더)
- **한 줄 뜻:** 문맥을 이용해 출력 토큰을 생성하는 구조.
- **쉽게:** 앞에 나온 내용을 바탕으로 다음 글을 이어 쓰는 부분.
- **수업 비교:** 자기회귀 생성 모델은 미래 토큰을 보지 않도록 Causal Mask를 사용한다.

### 41. Encoder–Decoder
- **한 줄 뜻:** 입력을 처리하는 Encoder와 출력을 생성하는 Decoder를 결합한 구조.
- **쉽게:** 글을 읽는 부분과 결과를 쓰는 부분을 나눠 둔 형태.
- **수업 예:** 번역, 요약 등 조건부 생성.

### 42. Hidden State (은닉 상태)
- **한 줄 뜻:** 모델 내부 계산을 거치면서 만들어진 토큰의 중간 숫자 표현.
- **쉽게:** 원래 토큰에 문맥 정보가 반영된 ‘가공 중인 숫자 묶음’.

### 43. RoPE (Rotary Position Embedding)
- **한 줄 뜻:** Attention 계산에 위치 정보를 회전 형태로 반영하는 방법.
- **쉽게:** 토큰의 위치 관계를 계산에 반영하는 여러 방법 중 하나.
- **수업 범위:** 자세한 수식보다는 ‘순서를 반영한다’는 목적을 이해하면 된다.

## 5교시 — Q/K/V·Attention·Mask

### 44. Query (Q, 쿼리)
- **한 줄 뜻:** 현재 토큰이 어떤 정보를 참고하고 싶은지를 나타내는 벡터.
- **쉽게:** “내가 지금 찾는 정보는 뭐지?”

### 45. Key (K, 키)
- **한 줄 뜻:** 다른 토큰이 어떤 특징을 갖는지 비교할 때 쓰는 벡터.
- **쉽게:** “내가 가진 정보는 이런 특징이 있어.”

### 46. Value (V, 밸류)
- **한 줄 뜻:** Attention 가중치에 따라 실제로 섞여 전달되는 정보 벡터.
- **쉽게:** “관련 있다고 판단되면 이 내용을 가져가.”

> **Q/K/V 암기:** Q는 **찾는 기준**, K는 **비교할 특징**, V는 **가져올 내용**. 실제로는 학습된 행렬을 이용해 만든 숫자 벡터다.

### 47. Attention Score (어텐션 점수)
- **한 줄 뜻:** Q와 K를 비교해 구한 토큰 간 관련 점수.
- **쉽게:** “얼마나 참고할 만한가?”에 대한 원점수.
- **주의:** 아직 확률이나 최종 가중치가 아니다.

### 48. Scale / Scaled Dot-Product Attention
- **한 줄 뜻:** Q와 K의 점수를 특징 차원 크기에 맞춰 조절하는 Attention 계산.
- **쉽게:** 점수가 지나치게 커지지 않도록 크기를 조정한다.
- **수업 수식:** `QKᵀ / √dₖ`.

### 49. Softmax (소프트맥스)
- **한 줄 뜻:** 여러 점수를 합이 1인 비율(확률 분포)로 바꾸는 함수.
- **쉽게:** 점수들을 ‘각 후보에 얼마만큼 비중을 줄지’로 바꾼다.
- **예시:** `[0.2, 0.3, 0.5]`처럼 합이 1이 된다.

### 50. Attention Weight (어텐션 가중치)
- **한 줄 뜻:** Softmax 등을 적용한 뒤 각 토큰 정보를 참고하는 비중.
- **쉽게:** A 토큰 20%, B 토큰 30%, C 토큰 50% 참고하는 식의 비율.
- **주의:** 이 비중만으로 모델의 판단 이유 전체를 설명할 수 없다.

### 51. Causal Mask (인과 마스크)
- **한 줄 뜻:** 현재 토큰보다 뒤에 있는 미래 토큰을 참조하지 못하게 하는 제한.
- **쉽게:** 문제를 풀 때 아직 공개되지 않은 뒷부분의 정답을 가리는 것.
- **차이:** Padding Mask는 **빈칸을 무시**, Causal Mask는 **미래를 가림**.

### 52. Multi-Head Attention (다중 헤드 어텐션)
- **한 줄 뜻:** 여러 Attention Head가 서로 다른 정보 관계를 학습할 수 있게 하는 방식.
- **쉽게:** 한 문장을 여러 관점에서 동시에 살펴보는 것.
- **주의:** Head 수가 많다고 무조건 좋은 모델이 되는 것은 아니다.

### 53. Attention Head (어텐션 헤드)
- **한 줄 뜻:** 독립적인 Q/K/V 투영과 Attention 계산을 수행하는 한 단위.
- **쉽게:** 여러 관점 중 한 관점을 맡은 계산 담당자.

### 54. Attention Matrix / Heatmap
- **Attention Matrix:** 토큰마다 다른 토큰을 얼마나 참고하는지 숫자로 정리한 표.
- **Heatmap:** 그 숫자의 크기를 색의 진하기 등으로 표시한 그림.
- **쉽게:** 어떤 위치를 많이 참고하는지 한눈에 확인하는 지도.

**수업 계산 흐름:** `Q와 K 비교 → Score 계산 → Mask 적용 → Softmax → Weight × V → 문맥 반영 결과`

## 6교시 — 학습·추론·출력 생성

### 55. Training (학습)
- **한 줄 뜻:** 정답과 예측의 차이를 줄이도록 모델의 가중치를 수정하는 과정.
- **쉽게:** 문제를 풀고 틀린 부분을 고쳐 가며 실력을 바꾸는 단계.

### 56. Inference (추론)
- **한 줄 뜻:** 학습된 가중치를 사용해 새 입력의 결과를 계산하는 과정.
- **쉽게:** 이미 공부한 상태로 새로운 문제에 답하는 단계.
- **핵심 차이:** 일반적인 추론에서는 가중치를 바꾸지 않는다.

### 57. Pretraining (사전학습)
- **한 줄 뜻:** 대규모 데이터로 모델의 기본 능력을 먼저 학습시키는 과정.
- **쉽게:** 특정 회사 업무를 배우기 전에 기본 교과를 넓게 공부하는 것.

### 58. Loss (손실)
- **한 줄 뜻:** 모델의 예측이 학습 목표와 얼마나 어긋났는지 나타내는 값.
- **쉽게:** 채점 후 계산한 오차 점수.

### 59. Gradient (기울기)
- **한 줄 뜻:** 손실이 가중치 변화에 따라 어떻게 달라지는지 알려주는 값.
- **쉽게:** 오차를 줄이려면 숫자를 어느 방향으로 조정해야 하는지 알려주는 힌트.

### 60. Backpropagation / `backward()` (역전파)
- **한 줄 뜻:** 손실로부터 각 가중치의 기울기를 계산하는 과정.
- **쉽게:** 결과의 오차를 거꾸로 따라가며 어디를 조정할지 계산한다.

### 61. Optimizer / `optimizer.step()` (최적화 도구)
- **한 줄 뜻:** 계산된 기울기를 이용해 모델 가중치를 갱신하는 방법·단계.
- **쉽게:** 계산한 수정 방향을 실제 모델 숫자에 반영한다.

### 62. Parameter / Weight (파라미터·가중치)
- **한 줄 뜻:** 모델이 학습을 통해 조정하는 내부 숫자.
- **쉽게:** 모델의 계산 방식에 영향을 주는 수많은 조절값.

### 63. Logit (로짓)
- **한 줄 뜻:** 다음 토큰 후보마다 모델이 계산한 확률 변환 전 점수.
- **쉽게:** 후보별 원점수.
- **주의:** Logit이 2라고 확률이 2%라는 뜻이 아니다.

### 64. LM Head (Language Modeling Head)
- **한 줄 뜻:** 모델 내부 표현을 Vocabulary의 각 토큰 후보 점수(Logits)로 바꾸는 출력 부분.
- **쉽게:** 내부 계산 결과를 ‘다음 토큰 후보별 점수표’로 만드는 장치.

### 65. Decoding (디코딩)
- **한 줄 뜻:** 다음 토큰 후보의 점수·확률에서 실제 출력할 토큰을 선택하는 과정.
- **쉽게:** 여러 답 후보 중 다음에 쓸 조각 하나를 고른다.

### 66. Greedy Decoding (그리디 디코딩)
- **한 줄 뜻:** 매번 가장 높은 점수의 토큰을 고르는 방법.
- **쉽게:** 매 순간 1등 후보만 선택한다.

### 67. Temperature (온도)
- **한 줄 뜻:** 토큰 선택 확률 분포가 얼마나 한쪽으로 몰리는지 조절하는 값.
- **쉽게:** 낮으면 높은 점수 후보에 더 집중하고, 높으면 다른 후보도 선택할 여지가 커진다.
- **주의:** 온도를 낮춘다고 사실이 자동으로 정확해지는 것은 아니다.

### 68. Top-k Sampling
- **한 줄 뜻:** 점수가 높은 상위 k개 후보 안에서 선택하는 방식.
- **쉽게:** 상위 5개만 후보로 두려면 `k=5`.

### 69. Top-p Sampling
- **한 줄 뜻:** 확률을 높은 순서로 더해 누적 확률 p에 이르는 후보 집합에서 선택하는 방식.
- **쉽게:** 누적 확률이 90% 정도에 도달할 때까지 후보를 모으는 방식(`p=0.9`).
- **차이:** Top-k는 **후보 개수**, Top-p는 **누적 확률**을 기준으로 한다.

### 70. Autoregressive Generation (자기회귀 생성)
- **한 줄 뜻:** 이미 주어진 토큰과 생성한 토큰을 바탕으로 다음 토큰을 하나씩 이어 만드는 방식.
- **쉽게:** 한 글 조각을 쓰고, 지금까지 쓴 내용을 참고해 다음 조각을 쓰는 일을 반복한다.

### 71. Prefill (프리필)
- **한 줄 뜻:** 생성 시작 전에 입력 문맥을 한 번 처리하는 단계.
- **쉽게:** 답변을 쓰기 전에 질문과 참고 자료를 먼저 읽는 단계.

### 72. KV Cache (키·밸류 캐시)
- **한 줄 뜻:** 이미 처리한 토큰의 Key·Value를 저장해 다음 토큰 생성 때 재사용하는 기능.
- **쉽게:** 앞에서 계산한 내용을 매번 처음부터 다시 계산하지 않도록 임시로 보관한다.
- **주의:** 장기 기억이 아니며 메모리를 사용한다.

### 73. Prompting / Instruction Tuning / Preference Alignment
- **Prompting:** 모델의 가중치는 그대로 두고 입력 지시·예시를 조정한다.
- **Instruction Tuning:** 지시와 응답 예시로 모델 가중치를 추가 학습한다.
- **Preference Alignment:** 선호 데이터 등을 활용해 응답 행동을 조정한다.
- **쉽게:** **질문 방식 바꾸기 / 추가 훈련하기 / 선호되는 응답 방향으로 조정하기**.

## 7교시 — RAG·Agent·서비스 검증

### 74. Prompt (프롬프트)
- **한 줄 뜻:** 모델에 전달하는 질문·지시·예시 등의 입력.
- **쉽게:** AI에게 주는 업무 요청서.

### 75. RAG (Retrieval-Augmented Generation, 검색 증강 생성)
- **한 줄 뜻:** 외부 문서를 검색해 그 내용을 모델 입력에 넣고 답변을 생성하는 방식.
- **쉽게:** AI가 기억만으로 답하는 대신 관련 자료를 찾아 읽고 답하게 하는 것.
- **예시:** 회사 규정 질문 → 관련 규정 검색 → LLM이 해당 자료를 참고해 답변.
- **주의:** RAG는 그 자리에서 모델 가중치를 다시 학습시키는 방식이 아니다.

### 76. Retriever (검색기)
- **한 줄 뜻:** 질문에 관련된 문서나 정보를 찾아오는 구성요소.
- **쉽게:** 필요한 자료를 찾아 주는 사서.

### 77. Vector DB (벡터 데이터베이스)
- **한 줄 뜻:** 임베딩 벡터를 저장하고 유사한 벡터를 검색하는 데 사용하는 저장·검색 시스템.
- **쉽게:** 문장 뜻을 숫자로 표현한 자료를 비교해 비슷한 내용을 찾는 창고.
- **수업 연결:** 이후 Embedding·Vector DB·RAG 수업에서 확장한다.

### 78. Chunking (청킹)
- **한 줄 뜻:** 긴 문서를 검색하기 쉬운 작은 구간으로 나누는 작업.
- **쉽게:** 두꺼운 책을 적당한 크기의 페이지 묶음으로 나누어 필요한 부분을 찾기 쉽게 만드는 것.
- **수업 연결:** 이후 RAG 구축 단계에서 다룬다.

### 79. Fine-tuning (파인튜닝, 미세조정)
- **한 줄 뜻:** 기존 모델을 추가 데이터로 학습시켜 특정 작업에 적응시키는 방법.
- **쉽게:** 기본 공부를 마친 사람에게 특정 업무를 추가 교육하는 것.
- **RAG와 차이:** RAG는 **자료를 찾아 입력에 제공**, Fine-tuning은 **가중치를 추가 학습**한다.

### 80. AI Agent (AI 에이전트)
- **한 줄 뜻:** LLM과 도구·상태·권한 등을 조합해 여러 단계의 작업을 처리하는 시스템.
- **쉽게:** 답변만 쓰는 것을 넘어, 허용된 기능을 사용해 일을 진행하도록 설계한 시스템.
- **주의:** LLM을 연결했다고 Agent가 자동으로 완성되지는 않는다.

### 81. Tool (도구)
- **한 줄 뜻:** Agent가 외부 API나 업무 시스템에서 실제 조회·수정 등의 작업을 수행할 때 사용하는 기능.
- **쉽게:** AI가 사용할 수 있도록 연결해 둔 업무용 버튼이나 기능.
- **주의:** 실제 실행 권한과 승인은 Backend에서 확인해야 한다.

### 82. Backend (백엔드)
- **한 줄 뜻:** 요청 처리, DB 연결, 권한 확인 등 서비스의 서버 쪽 기능.
- **쉽게:** 사용자 화면 뒤에서 실제 일을 처리하는 부분.
- **수업 연결:** FastAPI는 서비스 입구, PostgreSQL은 원본 데이터 저장 역할.

### 83. PostgreSQL
- **한 줄 뜻:** 데이터를 표(테이블) 형태로 저장·조회하는 관계형 데이터베이스 시스템.
- **쉽게:** 서비스에서 문서 정보와 기록을 보관하는 정리된 창고.
- **주의:** DB 자체가 LLM처럼 문장을 생성하는 것은 아니다.

### 84. Evaluation (평가)
- **한 줄 뜻:** 모델 출력의 품질을 기준에 따라 검사하는 것.
- **수업 기준:** 형식, 근거, 정확성, 재현성, 안전성.
- **쉽게:** 답변이 보기 좋기만 한지, 실제로 맞고 믿을 수 있는지 따로 채점한다.

### 85. Schema / JSON Schema (스키마)
- **한 줄 뜻:** 데이터가 어떤 필드와 형식으로 구성되어야 하는지 정한 규칙.
- **쉽게:** 답변에 `title`, `answer` 같은 칸이 꼭 있어야 한다는 서식 규칙.
- **주의:** 형식이 맞는다고 내용이 사실인 것은 아니다.

### 86. Metadata (메타데이터)
- **한 줄 뜻:** 데이터의 출처·제목·작성일 등 데이터에 대한 부가 정보.
- **쉽게:** 책 내용 자체가 아니라 책 제목·저자·출판일 같은 정보.

### 87. Untrusted Text (신뢰할 수 없는 텍스트)
- **한 줄 뜻:** 외부에서 가져와 그대로 지시로 믿어서는 안 되는 내용.
- **쉽게:** 검색된 문서에 ‘규칙을 무시하라’고 적혀 있어도 시스템 명령처럼 따르지 않는 것.

### 88. Logging / Reproducibility (로그·재현성)
- **Logging:** 실행 과정, 오류, 설정 등을 기록하는 것.
- **Reproducibility:** 같은 조건에서 결과를 다시 확인하고 설명할 수 있는 성질.
- **쉽게:** 무엇을 어떻게 실행했는지 남겨 나중에 문제를 추적할 수 있게 한다.

## 8교시 — 오늘 실습에서 용어가 쓰이는 순서

| 실습 | 직접 확인할 것 | 핵심 용어 |
|---|---|---|
| 1. Token 분석 | 문장을 나눈 조각·ID·개수 | Tokenizer, Token ID, Context |
| 2. Embedding 비교 | 숫자 벡터와 방향 유사도 | Vector, Dimension, Cosine Similarity |
| 3. Attention 계산 | Q/K/V, Mask, 행별 가중치 합 | Score, Softmax, Weight |
| 4. 출력 흐름 | 후보 점수에서 다음 토큰 선택 | Logit, Decoding, Inference |
| 5. 서비스 연결 설명 | 각 시스템이 맡는 역할 | FastAPI, PostgreSQL, RAG, Agent |

### Attention 계산을 말로 설명해 보기

1. **Q와 K를 비교**해 관련 점수를 계산한다.
2. **Mask**로 참고하면 안 되는 위치를 가린다.
3. **Softmax**로 점수를 비율로 바꾼다.
4. **V를 가중합**해 문맥을 반영한 결과를 만든다.

수업의 간단한 예시에서 마지막 토큰의 가중치가 `[0.25, 0.25, 0.50]`이고 V가 `[1,0]`, `[0,1]`, `[1,1]`이라면 결과는 `[0.75, 0.75]`이다.

## 가장 많이 헷갈리는 용어 비교

| 헷갈리는 두 용어 | 차이 한 줄 |
|---|---|
| **Token vs Token ID** | 글 조각 vs 그 조각의 번호 |
| **Token ID vs Embedding** | 정수 번호 vs 연속된 숫자 벡터 |
| **Token Embedding vs Sentence Embedding** | 토큰 하나의 표현 vs 문장 전체의 표현 |
| **Attention vs FFN** | 토큰끼리 정보 섞기 vs 각 토큰 정보 가공하기 |
| **Q vs K vs V** | 찾는 기준 vs 비교 특징 vs 전달 내용 |
| **Score vs Weight** | 원점수 vs Softmax 후 참고 비중 |
| **Padding Mask vs Causal Mask** | 빈칸 무시 vs 미래 위치 가리기 |
| **Logit vs Probability** | 후보 원점수 vs 확률 분포 |
| **Training vs Inference** | 가중치 변경 vs 학습된 가중치로 결과 생성 |
| **RAG vs Fine-tuning** | 외부 자료 검색·제공 vs 모델 추가 학습 |
| **LLM vs RAG vs Agent** | 언어 생성 모델 vs 검색 근거 활용 방식 vs 도구·상태를 활용한 작업 시스템 |
| **Context Window vs KV Cache** | 참고 가능한 토큰 범위 vs 이전 계산의 K/V 재사용 |
| **FastAPI vs PostgreSQL vs LLM** | 요청 처리 vs 데이터 저장 vs 언어 계산·생성 |

## 복습용 핵심 15개 — 이 정도는 먼저 기억하기

1. **LLM:** 대규모 언어 모델.
2. **Token:** 모델이 처리하는 글 조각.
3. **Tokenizer:** 글을 토큰으로 나누는 도구.
4. **Token ID:** 토큰에 붙은 숫자 번호.
5. **Embedding:** 토큰·문장을 숫자 벡터로 표현.
6. **Context Window:** 한 번에 참고할 수 있는 토큰 범위.
7. **Transformer:** Attention·FFN 등을 반복하는 모델 구조.
8. **Self-Attention:** 토큰끼리 서로 참고할 정보를 계산.
9. **Q/K/V:** 찾는 기준 / 비교 특징 / 전달 내용.
10. **Mask:** 참고하면 안 되는 위치를 가리는 장치.
11. **Softmax:** 점수를 합이 1인 비율로 변환.
12. **Logit:** 다음 토큰 후보의 원점수.
13. **Training:** 모델 가중치를 수정하는 학습.
14. **Inference:** 학습된 모델로 답변을 생성하는 계산.
15. **RAG:** 외부 자료를 검색해 답변 근거로 제공.

- [ ] 학습과 추론에서 가중치가 어떻게 다른지 설명할 수 있다.
- [ ] RAG가 모델을 다시 학습시키는 것은 아니라는 점을 설명할 수 있다.
