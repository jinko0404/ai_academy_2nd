전체 구조 설명

1. 사용자 측에서 에이전트에 질문을 입력한다.

2. FastAPI에서 사용자의 질문을 접수하고 적절한 Python 코드에 요청을 연결한다.

3. Pydantic에서 질문 형식을 검사한다.
	- 사용자가 보낸 데이터가 개발자가 정해 놓은 규칙에 맞는지

4. Pydantic검사가 통과되면 FastAPI가 연결한 Python함수가 실행되며 Retriever로 요청 신호가 전송된다.

5. 질문을 전달받은 Retriever는 해당 질문과 관련된 관련 문서를 검색한다.
	- 이 과정에서 질문이 비어있진 않은지, 검색 갯수가 이상하지 않은지의 여부 등의 입력 조건을 검토해야한다.

6. 검색 준비가 끝나면 Retriever는 Embedding 모델을 사용해 질문을 벡터로 변환한다.
	- 해당 과정은 컴퓨터가 질문과 저장된 문서가 얼마나 비슷한지 관련이 있는지를 계산 하기 위한 과정이다.
	- 질문을 384개의 숫자로 표현한다(이 384개의 숫자 묶음을 Vector라고 부른다.)

7. PstgreSQL과 pgvector가 관련 자료를 찾는다.
	- 질문이 숫자(Vector)로 변환 되었다면 Retriever는 이를 이용해 DB(PstgreSQL)에 검색을 요청한다.
	- 이 과정에서 pgvector가 PstgreSQL에서 벡터를 저장하고, 비슷한 벡터값을 가진 자료를 검색할 수 있게 해주는 기능이다.
	- pgvector는 질문 벡터와 문서 벡터 사이의 거리를 계산하여 거리 값이 가장 작은 가까운 문서 순으로 후보를 선정한다.
	- 여기서 주의해야할 것은 거리 값이 가장 작은 문서라 해서 무조건 정답은 아니라는 것이다.

8. Retriever가 검색결과를 반환한다.
	- PstgreSQL이 검색결과를 돌려주면 Retriever는 이를 정리하여 자신을 호출했던 FastAPI가 연결해준 함수로 값을 반환해준다
