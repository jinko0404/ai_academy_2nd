# Day 23 · Embedding과 pgvector — 흐름부터 이해하는 통합 학습 노트

> 기준: Day23_Embedding_pgvector_정리.md (2026-11-18). 기존 쉬운 용어 정리 107개를 뒤에 수록했다. 숫자 예시는 설명용이며 실제 모델 실행 결과가 아니다.

## Part A. 전체 흐름과 작동 원리

### A1. 오늘 무엇을 만드는가?

지난 수업에는 사람이 필요한 지식 ID를 선택해 LLM에 전달했다. 오늘은 그 선택 작업을 자동화한다. 질문에 가까운 자료의 ID와 원문을 반환하는 **검색기(Retriever)** 를 만든다. 아직 답변을 생성하지 않는다.

도서관에 비유하면 문서를 등록하는 직원, 책을 찾아주는 사서, 책을 읽고 답변을 작성하는 사람이 각각 다른 역할이다.

| 구성 | 비유 | 실제 역할 |
|---|---|---|
| E5 모델 | 책의 내용을 좌표로 표시하는 분류기 | 텍스트를 384차원 벡터로 변환 |
| PostgreSQL | 책과 목록을 보관하는 도서관 | ID, 원문, 메타데이터 저장 |
| pgvector | 가까운 좌표의 책을 찾는 기능 | 벡터 저장과 거리 계산 |
| Retriever | 사서 | 질문을 받아 후보 원문 반환 |
| LLM | 자료를 읽고 글을 쓰는 사람 | 후속 수업에서 Context 기반 답변 생성 |

### A2. 전체 시스템: 사전 준비와 실시간 검색

```text
[사전 준비: 문서가 등록되거나 변경될 때]
지식 ID + 제목 + 내용
    ↓ passage: 접두어
Embedding 모델(E5)
    ↓ 문서별 384개 숫자
PostgreSQL + pgvector에 원문과 벡터 함께 저장
    ↓
검색 준비 완료

[실시간 검색: 질문이 들어올 때마다]
사용자 질문
    ↓ query: 접두어
같은 Embedding 모델(E5)
    ↓ 질문 벡터 384개 숫자
pgvector: 저장된 문서 벡터와 거리 비교
    ↓ 가까운 순서로 정렬
Top-k: 최대 k개 선택
    ↓
후보 ID + 제목 + 원문 + 거리 반환  ← 오늘의 종료 지점
    ↓ (후속 RAG 수업)
관련성·권한 확인 → Context → LLM → 답변·출처 검증
```

왜 두 경로를 나눌까? 문서 9건을 질문마다 다시 변환하면 같은 일을 반복하기 때문이다. 문서와 모델 계약이 그대로라면 문서 벡터는 저장해 재사용한다.

### A3. 실제 질문 하나로 끝까지 따라가기

**예제 질문: 서버는 어디에서 실행하나요?**

| 단계 | 입력 | 처리 | 출력 |
|---|---|---|---|
| 1. 자료 등록 | ID 102, 서버 실행, 프로젝트 폴더에서 서버를 실행합니다. | 제목과 본문을 연결 | passage: 서버 실행 프로젝트 폴더에서 서버를 실행합니다. |
| 2. 문서 변환 | passage 문자열 | E5 encode 및 정규화 | 문서 벡터 (384,) |
| 3. 저장 | ID, 원문, 벡터 | 동일 행 INSERT/UPDATE | 검색 가능한 DB 레코드 |
| 4. 질문 준비 | 서버는 어디에서 실행하나요? | query: 접두어 추가 | query: 서버는 어디에서 실행하나요? |
| 5. 질문 변환 | query 문자열 | 같은 모델 encode | 질문 벡터 (384,) |
| 6. 거리 비교 | 질문 벡터와 문서 벡터 | 코사인 거리 계산 | 문서별 거리 |
| 7. 후보 선택 | 거리와 k=3 | ASC 정렬 후 LIMIT | 최대 3건의 ID와 원문 |
| 8. 검토 | 후보 원문 | 실제 질문에 필요한 사실 확인 | 관련 자료 102 등 판단 |

102는 원문에 실행 위치가 명시되어 관련 자료다. 106은 DB 연결 설정에 관한 문서라 주제는 비슷하지만 직접 답을 주지 않는다. 검색 순위 자체는 실제 실행과 평가로 확인해야 한다.

### A4. 벡터가 가까운지 어떻게 판단하는가?

지도에서 두 장소의 위치를 비교하듯 문장을 숫자 좌표로 비교한다. 다만 실제 384개 좌표를 업무 의미 하나씩에 대응시킬 수는 없다.

설명용 질문 q=(1,0), 문서 A=(0.8,0.6), 문서 B=(0,1)을 생각해 보자.

| 문서 | 코사인 유사도 | 코사인 거리 | 가까운 순서 |
|---|---:|---:|---|
| A | 0.8 | 0.2 | 1 |
| B | 0 | 1 | 2 |

유사도는 클수록, 거리는 작을수록 가깝다. `거리 = 1 - 유사도`이므로 pgvector의 `<=>` 결과는 ASC로 정렬한다. 0.8은 정답 확률 80%가 아니다.

정규화는 (3,4)를 (0.6,0.8)로 바꾸듯 방향을 유지하면서 길이를 1로 맞춘다. 두 벡터가 모두 단위 벡터라면 내적과 코사인 유사도가 같고 L2 거리의 가까운 순서도 일치한다. 영벡터나 NaN, Inf는 검증 단계에서 차단한다.

### A5. 왜 같은 모델을 사용해야 할까?

서로 다른 지도 좌표 체계에서 숫자 두 개가 같아도 같은 장소를 의미하지 않을 수 있다. 벡터도 마찬가지다. 384차원이라는 크기만 같다고 같은 공간은 아니다.

오늘의 계약은 `intfloat/multilingual-e5-small`, 384차원, 질문 `query: `, 본문 `passage: `, 정규화 적용이다. 모델 ID와 revision, 입력 규칙을 기록한다. 입력 최대 512토큰과 출력 384차원은 다른 개념이다. 모델이나 전처리 계약을 바꾸면 새 계약에 맞춰 문서·질문 벡터를 생성해야 한다.

### A6. pgvector 설치 과정은 왜 네 단계인가?

```text
서버 확장 파일 설치 → 해당 DB에서 CREATE EXTENSION
                         ↓
Python에 pgvector 패키지 설치 → 연결마다 register_vector(conn)
```

첫 두 단계는 DB 서버의 기능, 뒤 두 단계는 Python에서 그 기능을 이용하기 위한 연동이다. pip만 설치하면 서버에 DLL이 생기지는 않는다.

| 단계 | 작업 위치 | 성공 확인 |
|---|---|---|
| 서버 파일 빌드·배치 | 관리자 x64 Native Tools Command Prompt | vector.dll, control, SQL 파일 |
| DB 활성화 | pgAdmin의 수업용 DB | pg_extension에 vector 버전 |
| Python 패키지 설치 | 기존 가상환경 Git Bash | import, pip check |
| 연결 타입 등록 | Python | 3차원 벡터 전달·거리 계산 성공 |

수업 자료의 Windows 빌드 후보는 v0.8.7이며 실기기 빌드 성공은 확인되지 않았다고 명시한다. 설치 성공 여부는 PC에서 확인한다. 구체적인 명령과 오류 대응은 원본 4장을 참고한다.

### A7. 코드가 실제로 움직이는 순서

**1. 모델 로딩 및 Embedding** (모델은 한 번 로딩해 재사용)

```python
from sentence_transformers import SentenceTransformer

model = SentenceTransformer('intfloat/multilingual-e5-small', device='cpu')
# 문서의 제목과 본문을 검색용 벡터로 변환
passages = ['passage: 서버 실행 프로젝트 폴더에서 서버를 실행합니다.']
doc_vecs = model.encode(passages, normalize_embeddings=True)
# 사용자 질문을 같은 모델로 변환
query_vecs = model.encode(['query: 서버는 어디에서 실행하나요?'],
                          normalize_embeddings=True)
qvec = query_vecs[0]
```

문서 9건이라면 doc_vecs의 shape는 (9,384), 질문 한 건은 (1,384), qvec은 (384,)이다. encode는 모델 학습이 아니라 추론이다. 실제 저장 전 shape, 유한값, norm 및 ID 대응을 검증한다.

**2. DB 저장 구조**

```sql
CREATE TABLE IF NOT EXISTS day23_search_docs (
  id integer PRIMARY KEY,
  title text NOT NULL,
  content text NOT NULL,
  category text NOT NULL,
  source_version text NOT NULL,
  embedding_model text NOT NULL,
  embedding vector(384) NOT NULL
);
```

벡터만 저장하면 사용자에게 보여줄 원문을 찾기 어렵다. ID와 원문, 벡터를 함께 저장한다. 실제 INSERT/UPDATE에서는 같은 문서의 원문과 벡터를 한 트랜잭션으로 관리한다. 기존 knowledge 테이블은 보존한다.

**3. Top-k 검색** (conn은 연결 및 register_vector를 완료했다고 가정)

```python
sql = """
SELECT id, title, content, category, source_version,
       embedding <=> %s AS cosine_distance
FROM day23_search_docs
ORDER BY embedding <=> %s ASC
LIMIT %s
"""
rows = conn.execute(sql, (qvec, qvec, 3)).fetchall()
```

- SELECT: 가져올 정보와 거리 점수를 지정한다.
- FROM: 검색 대상 테이블을 지정한다.
- ORDER BY: 계산한 거리가 작은 자료부터 정렬한다.
- LIMIT: 최대 3개만 반환한다.
- 두 개의 벡터 파라미터에는 같은 qvec을 전달한다. 필터를 추가한다면 WHERE의 파라미터 위치도 맞춘다.

위 조각은 실행 흐름을 설명하는 예시이며 DB 연결·문서 INSERT·검증 코드를 포함한 완성 실행 스크립트는 아니다.

### A8. 데이터가 많아지면 왜 인덱스가 필요한가?

Exact Search는 비교 대상 문서 전체의 거리를 계산한다. HNSW는 벡터를 연결한 그래프를 따라 일부 후보를 탐색하는 ANN 방식이다. 도서관의 모든 책을 훑는 방법과 안내 지도를 따라 가까운 책장부터 찾는 방법의 차이다.

```text
정확 검색으로 기준 결과 확보
    ↓
HNSW 인덱스 생성 (vector_cosine_ops)
    ↓
EXPLAIN (ANALYZE, BUFFERS)로 실제 실행 계획 확인
    ↓
같은 질문의 후보 누락 여부·응답시간 비교
```

인덱스 생성 성공, 사용 여부, 품질 향상은 별개다. 9건에서는 Seq Scan이 정상일 수 있다. ANN은 정확 검색 후보를 놓칠 수 있고 필터 적용 뒤 k개 미만이 될 수도 있다. `EXPLAIN`의 cost는 밀리초가 아니다.

### A9. 검색 성공과 답변 성공은 다르다

질문: 실습 파일은 몇 년 동안 보관하나요?

찾은 ID 101: 실습 파일은 개인 폴더에 보관합니다.

이 문장은 보관 **장소**를 알려주지만 **기간**을 알려주지 않는다. 따라서 검색 결과가 있어도 기간을 답할 수 없다. 후속 RAG에서는 정보 부족으로 처리해야 한다.

| 상태 | 상황 | 처리 방향 |
|---|---|---|
| empty | 정상 조회 결과 0건 | 조건·자료 범위 확인 |
| error | DB 연결 또는 SQL 오류 | 장애 기록·원인 확인 |
| irrelevant | 후보는 있지만 필요한 정보 없음 | 근거 부족으로 판단 |

`retrieved_ids`는 검색 후보 전체, `included_ids`는 검토 후 Context에 넣은 자료, `source_ids`는 최종 답변에서 인용한 자료다. 예: [101,102,107] → [102] → [102]. ID 포함 관계와 원문 근거를 각각 검증한다.

### A10. 이후 RAG 수업으로 연결되는 과정

오늘의 검색 모듈은 `validate_request → embed_query → search_exact → format_results → record_run`으로 나뉜다. 내일은 문서 Parsing·Chunking·Metadata를 더하고, 다음 수업에서는 검색 결과를 선별해 Context와 LLM Client에 연결한다. 검색기는 자료를 찾고 LLM은 그 자료를 이용해 답을 작성한다.

**한 문장으로 설명하기:** 문서와 질문을 동일 모델 계약으로 벡터화하고, pgvector에서 가까운 벡터의 원문을 찾은 뒤, 실제 근거가 되는지 검토한다.

## Part B. 핵심 용어 사전 (기존 107개 용어)

아래는 앞에서 이해한 흐름에 등장하는 용어를 개별적으로 복습하는 부분이다.

## 1. Embedding과 Semantic Search

### 1. Embedding

-   **한 줄 뜻:** 텍스트를 고정 길이의 실수 벡터로 바꾸는 것
-   **쉽게:** 문장의 의미를 검색용 숫자 좌표로 표현한다.
-   **예시·기억:** 서버 실행 방법과 서버 어디서 켜요는 서로 가까운 벡터가 될 수 있다.

### 2. Embedding Model

-   **한 줄 뜻:** 텍스트를 벡터로 변환하는 학습된 모델
-   **쉽게:** 문장을 검색용 좌표로 바꾸는 변환기다.
-   **예시·기억:** 오늘은 E5-small을 사용한다. 답변을 작성하는 LLM과 역할이 다르다.

### 3. Vector

-   **한 줄 뜻:** 순서가 있는 숫자 배열
-   **쉽게:** 지도에서 위치를 좌표로 나타내듯 문장을 숫자 묶음으로 표현한다.
-   **예시·기억:** \[0.8, 0.6\]은 설명용 2차원 벡터다.

### 4. Dimension (차원)

-   **한 줄 뜻:** 벡터에 들어 있는 숫자의 개수
-   **쉽게:** 좌표를 표현하는 숫자 칸의 수다.
-   **예시·기억:** 384차원은 숫자 384개이지 384글자가 아니다.

### 5. Semantic Search (의미 검색)

-   **한 줄 뜻:** 내용상 가까운 자료를 찾는 검색
-   **쉽게:** 표현이 달라도 뜻이 비슷한 자료를 찾는다.
-   **예시·기억:** 서버 어디서 켜요 → 프로젝트 폴더에서 서버를 실행합니다.

### 6. Keyword Search (키워드 검색)

-   **한 줄 뜻:** 단어 등 표면 표현을 중심으로 찾는 검색
-   **쉽게:** 문서에서 특정 단어를 찾는 기능과 비슷하다.
-   **예시·기억:** 서버라는 단어가 있는 문서를 찾는다.

### 7. Retriever

-   **한 줄 뜻:** 질문과 관련된 자료 후보를 가져오는 검색 구성요소
-   **쉽게:** 도서관에서 질문에 맞는 책을 찾아주는 사서와 비슷하다.
-   **예시·기억:** retrieve(question, k=3)은 최대 3개 후보를 반환한다.

### 8. Retrieval

-   **한 줄 뜻:** 관련 자료 후보를 가져오는 과정
-   **쉽게:** 답을 쓰기 전에 참고할 자료를 찾는 단계다.
-   **예시·기억:** 지식 102의 제목과 본문을 가져온다.

### 9. Symmetric Search (대칭 검색)

-   **한 줄 뜻:** 비슷한 성격의 입력끼리 비교하는 검색
-   **쉽게:** 질문과 질문을 비교한다.
-   **예시·기억:** FAQ의 기존 질문과 새 질문 비교.

### 10. Asymmetric Search (비대칭 검색)

-   **한 줄 뜻:** 서로 다른 역할의 입력을 비교하는 검색
-   **쉽게:** 짧은 질문으로 설명이 담긴 본문을 찾는다.
-   **예시·기억:** 오늘의 질문 → 지식 본문 검색.

### 11. Knowledge ID

-   **한 줄 뜻:** 각 지식 자료를 구분하는 식별자
-   **쉽게:** 책마다 붙은 고유 번호와 같다.
-   **예시·기억:** 102는 서버 실행 안내다.

### 12. Original Text (원문)

-   **한 줄 뜻:** 실제로 답변 근거로 사용할 텍스트
-   **쉽게:** 벡터는 찾기 위한 좌표이고 원문은 읽을 내용이다.
-   **예시·기억:** 102의 본문은 프로젝트 폴더에서 서버를 실행합니다.

### 13. Data Contract (데이터 계약)

-   **한 줄 뜻:** 입력과 저장 데이터가 지켜야 할 규칙
-   **쉽게:** 함수나 DB가 서로 약속한 형식이다.
-   **예시·기억:** ID·제목·본문·버전을 연결한다.

### 14. Document Embedding / Query Embedding

-   **한 줄 뜻:** 문서 벡터와 질문 벡터
-   **쉽게:** 문서는 미리 변환해 저장하고 질문은 들어올 때 변환한다.
-   **예시·기억:** 문서 9건을 질문마다 다시 변환할 필요가 없다.

## 2. Vector · Similarity · Distance

### 15. Similarity (유사도)

-   **한 줄 뜻:** 두 벡터가 얼마나 비슷한지 나타내는 값
-   **쉽게:** 비슷할수록 높은 점수를 받는다고 생각하면 된다.
-   **예시·기억:** Cosine similarity 0.8이 0.2보다 가깝다.

### 16. Distance (거리)

-   **한 줄 뜻:** 두 벡터가 얼마나 떨어져 있는지 나타내는 값
-   **쉽게:** 가까운 목적지가 더 짧은 거리에 있는 것과 같다.
-   **예시·기억:** 거리 0.2가 0.8보다 가깝다.

### 17. Dot Product (내적)

-   **한 줄 뜻:** 같은 위치의 숫자끼리 곱한 뒤 더한 값
-   **쉽게:** 방향뿐 아니라 벡터 길이에도 영향을 받는 비교값이다.
-   **예시·기억:** (1,0)·(0.8,0.6)=0.8.

### 18. Cosine Similarity (코사인 유사도)

-   **한 줄 뜻:** 두 벡터 방향의 유사도
-   **쉽게:** 화살표가 같은 방향을 향할수록 높다.
-   **예시·기억:** 범위 -1\~1, 같은 방향 1, 직각 0, 반대 방향 -1.

### 19. Cosine Distance (코사인 거리)

-   **한 줄 뜻:** 1에서 코사인 유사도를 뺀 값
-   **쉽게:** 유사도를 거리 방식으로 뒤집어 표현한다.
-   **예시·기억:** 유사도 0.8이면 거리 0.2다.

### 20. L2 Norm (벡터 길이)

-   **한 줄 뜻:** 원점에서 벡터 끝까지의 길이
-   **쉽게:** 화살표 자체의 길이다.
-   **예시·기억:** (3,4)의 길이는 5다.

### 21. L2 Distance (유클리드 거리)

-   **한 줄 뜻:** 두 벡터 끝점 사이의 직선거리
-   **쉽게:** 지도에서 두 위치 사이의 직선거리와 같다.
-   **예시·기억:** (1,0)과 (0.8,0.6)의 거리는 약 0.6325다.

### 22. Normalization (정규화)

-   **한 줄 뜻:** 벡터를 자신의 길이로 나누는 과정
-   **쉽게:** 화살표 방향은 그대로 두고 길이를 1로 맞춘다.
-   **예시·기억:** (3,4) → (0.6,0.8).

### 23. Unit Vector (단위 벡터)

-   **한 줄 뜻:** 길이가 1인 벡터
-   **쉽게:** 길이 차이를 없앤 화살표다.
-   **예시·기억:** 단위 벡터끼리는 내적과 코사인 유사도가 같다.

### 24. Zero Vector (영벡터)

-   **한 줄 뜻:** 모든 좌표가 0인 벡터
-   **쉽게:** 길이가 0이라 방향을 비교할 수 없다.
-   **예시·기억:** \[0,0\]은 코사인 계산에서 분모가 0이 된다.

### 25. NaN / Inf

-   **한 줄 뜻:** 정상적인 유한 실수가 아닌 값
-   **쉽게:** 계산이나 데이터 처리 과정의 이상 신호다.
-   **예시·기억:** 저장 전에 np.isfinite로 검사한다.

### 26. Threshold (임계값)

-   **한 줄 뜻:** 판정을 나누는 기준값
-   **쉽게:** 어느 점수 이상을 통과시킬지 정한 선이다.
-   **예시·기억:** 모델 평가 없이 유사도 0.8을 정답 기준으로 고정하지 않는다.

### 27. ASC / DESC

-   **한 줄 뜻:** 오름차순 / 내림차순
-   **쉽게:** 작은 값부터 / 큰 값부터 정렬한다.
-   **예시·기억:** 코사인 거리 검색은 ASC다.

## 3. Sentence Transformers

### 28. Sentence Transformers

-   **한 줄 뜻:** 문장 임베딩 모델을 불러와 실행하는 Python 라이브러리
-   **쉽게:** 모델을 사용하기 위한 도구 상자다.
-   **예시·기억:** SentenceTransformer(MODEL_ID)로 모델을 로드한다.

### 29. multilingual-e5-small

-   **한 줄 뜻:** 수업에서 사용하는 다국어 검색용 임베딩 모델
-   **쉽게:** 한국어 질문과 지식 본문을 비교할 수 있게 변환한다.
-   **예시·기억:** 모델 ID는 intfloat/multilingual-e5-small, 출력 384차원.

### 30. Pretrained Model (사전학습 모델)

-   **한 줄 뜻:** 미리 학습을 마친 모델
-   **쉽게:** 이미 훈련된 변환기를 가져다 쓰는 것이다.
-   **예시·기억:** encode할 때 모델을 새로 학습하지 않는다.

### 31. Model ID / Revision

-   **한 줄 뜻:** 모델 이름과 구체적인 버전
-   **쉽게:** 같은 제품명이라도 버전을 구별하는 것과 같다.
-   **예시·기억:** 모델 ID와 revision을 기록한다.

### 32. Prefix (접두어)

-   **한 줄 뜻:** 입력 앞에 붙이는 역할 표시
-   **쉽게:** 모델에게 지금 입력이 질문인지 본문인지 알려준다.
-   **예시·기억:** E5의 query: 와 passage: 는 다른 모델의 범용 문법이 아니다.

### 33. query:

-   **한 줄 뜻:** E5 질문 입력용 접두어
-   **쉽게:** 검색하려는 질문이라는 표시다.
-   **예시·기억:** query: 서버는 어디에서 실행하나요?

### 34. passage:

-   **한 줄 뜻:** E5 본문 입력용 접두어
-   **쉽게:** 검색 대상 자료라는 표시다.
-   **예시·기억:** passage: 서버 실행 프로젝트 폴더에서 서버를 실행합니다.

### 35. encode

-   **한 줄 뜻:** 텍스트를 벡터로 변환하는 메서드
-   **쉽게:** 문장을 숫자 묶음으로 바꾸는 실행 버튼이다.
-   **예시·기억:** model.encode(passages, normalize_embeddings=True)

### 36. Inference (추론)

-   **한 줄 뜻:** 학습된 모델로 결과를 계산하는 과정
-   **쉽게:** 이미 배운 규칙을 새 입력에 적용한다.
-   **예시·기억:** E5의 encode는 추론이다.

### 37. Shape

-   **한 줄 뜻:** 배열의 각 축 크기
-   **쉽게:** 표의 행·열 개수와 같은 배열 구조다.
-   **예시·기억:** 문서 9개는 (9,384), 질문 1개는 (1,384).

### 38. Token Limit

-   **한 줄 뜻:** 모델이 처리할 수 있는 입력 토큰 상한
-   **쉽게:** 입력의 최대 길이다.
-   **예시·기억:** E5-small 입력 512 tokens, 출력은 384차원. 둘은 다른 개념이다.

### 39. Batch Size

-   **한 줄 뜻:** 한 번에 처리하는 입력 개수
-   **쉽게:** 자료를 여러 장씩 묶어서 처리하는 것과 같다.
-   **예시·기억:** batch_size=8.

### 40. Vector Contract (벡터 계약)

-   **한 줄 뜻:** 벡터를 만드는 모델과 전처리 규칙
-   **쉽게:** 같은 좌표계로 비교하기 위한 약속이다.
-   **예시·기억:** 모델 ID·revision·접두어·차원·정규화가 일치해야 한다.

### 41. Validation (검증)

-   **한 줄 뜻:** 입력이나 출력이 규칙에 맞는지 검사
-   **쉽게:** 잘못된 자료를 DB에 넣기 전에 걸러낸다.
-   **예시·기억:** shape, 유한값, norm, ID 대응을 확인한다.

## 4. PostgreSQL과 pgvector 설치

### 42. PostgreSQL

-   **한 줄 뜻:** 관계형 데이터베이스 관리 시스템
-   **쉽게:** 표 형태로 자료를 저장하고 SQL로 조회하는 시스템이다.
-   **예시·기억:** 오늘 환경은 PostgreSQL 18.6.

### 43. pgvector

-   **한 줄 뜻:** PostgreSQL에서 벡터 저장과 검색을 지원하는 확장
-   **쉽게:** 일반 DB에 벡터 거리 계산 기능을 추가한다.
-   **예시·기억:** 모델을 실행하는 것이 아니라 이미 만든 벡터를 검색한다.

### 44. Extension (확장)

-   **한 줄 뜻:** DB에 추가 기능을 제공하는 구성 요소
-   **쉽게:** 기존 프로그램에 기능을 추가하는 플러그인과 비슷하다.
-   **예시·기억:** CREATE EXTENSION vector.

### 45. pgAdmin

-   **한 줄 뜻:** PostgreSQL 관리용 그래픽 도구
-   **쉽게:** DB를 관리하며 SQL을 실행하는 화면이다.
-   **예시·기억:** Query Tool에서 확장 활성화를 확인한다.

### 46. Build Tools

-   **한 줄 뜻:** 소스 코드를 실행 가능한 파일로 만드는 도구
-   **쉽게:** 조립 설명서를 실제 부품으로 만드는 작업 도구와 비슷하다.
-   **예시·기억:** Visual Studio C++ Build Tools, MSVC, Windows SDK.

### 47. Compiler / Build

-   **한 줄 뜻:** 소스를 변환하는 프로그램 / 결과 파일을 만드는 작업
-   **쉽게:** 소스 코드를 서버가 사용할 파일로 조립한다.
-   **예시·기억:** cl과 nmake로 vector.dll을 만든다.

### 48. x64 Native Tools Command Prompt

-   **한 줄 뜻:** 64비트 개발 도구가 설정된 Windows 명령창
-   **쉽게:** 일반 터미널과 달리 빌드에 필요한 환경이 준비되어 있다.
-   **예시·기억:** 오늘 pgvector 소스 빌드에 사용한다.

### 49. PGROOT

-   **한 줄 뜻:** PostgreSQL 설치 최상위 폴더를 지정하는 변수
-   **쉽게:** 빌드 도구에 PostgreSQL이 있는 위치를 알려준다.
-   **예시·기억:** C:`\Program `{=tex}Files`\PostgreSQL`{=tex}\\18 (bin이나 data가 아님).

### 50. DLL / Control / SQL 파일

-   **한 줄 뜻:** 확장 실행 코드와 설치 정보 및 SQL 정의 파일
-   **쉽게:** 서버가 확장을 인식하고 작동시키는 부품들이다.
-   **예시·기억:** vector.dll, vector.control, vector--\*.sql.

### 51. CREATE EXTENSION

-   **한 줄 뜻:** 현재 DB에서 확장을 활성화하는 SQL
-   **쉽게:** 설치된 기능을 해당 DB에서 사용하도록 켠다.
-   **예시·기억:** 다른 DB에는 자동 적용되지 않는다.

### 52. Python Virtual Environment (가상환경)

-   **한 줄 뜻:** 프로젝트별 Python 패키지 환경
-   **쉽게:** 프로젝트마다 분리된 도구 상자다.
-   **예시·기억:** 기존 가상환경을 재사용한다.

### 53. Psycopg

-   **한 줄 뜻:** Python에서 PostgreSQL에 연결하는 드라이버
-   **쉽게:** Python과 DB 사이의 통역 창구다.
-   **예시·기억:** psycopg.connect로 연결한다.

### 54. pgvector Python Adapter

-   **한 줄 뜻:** Python 벡터와 DB vector 타입을 연동하는 패키지
-   **쉽게:** 두 프로그램 사이의 데이터 형식을 맞춘다.
-   **예시·기억:** pip install pgvector는 서버 DLL을 설치하지 않는다.

### 55. register_vector

-   **한 줄 뜻:** DB 연결에 vector 타입 변환을 등록하는 함수
-   **쉽게:** 현재 연결에 벡터 형식을 이해하도록 알려준다.
-   **예시·기억:** 연결마다 register_vector(conn) 호출.

### 56. .env

-   **한 줄 뜻:** 프로젝트의 설정값을 별도 보관하는 파일
-   **쉽게:** 코드에 비밀번호를 직접 적지 않고 설정으로 분리한다.
-   **예시·기억:** PGHOST, PGPORT, PGDATABASE, PGUSER, PGPASSWORD.

### 57. Transaction (트랜잭션)

-   **한 줄 뜻:** 여러 DB 작업을 하나의 작업 단위로 처리하는 것
-   **쉽게:** 원문과 벡터를 함께 저장하거나 실패하면 함께 취소한다.
-   **예시·기억:** COMMIT은 확정, ROLLBACK은 취소.

### 58. pg_config

-   **한 줄 뜻:** PostgreSQL 설치 정보 조회 도구
-   **쉽게:** 서버의 버전과 개발 파일 경로를 확인한다.
-   **예시·기억:** pg_config.exe --version.

### 59. pg_available_extensions / pg_extension

-   **한 줄 뜻:** 제공 가능한 확장 / 현재 DB에 설치된 확장 정보
-   **쉽게:** 설치 가능 목록과 실제 활성화 목록의 차이다.
-   **예시·기억:** vector 행과 extversion을 별도로 확인한다.

## 5. pgvector 저장과 Top-k

### 60. vector(384)

-   **한 줄 뜻:** 384차원 벡터를 저장하는 DB 자료형
-   **쉽게:** 숫자 384개가 들어가는 전용 칸이다.
-   **예시·기억:** 차원은 검사하지만 모델이 같은지는 보장하지 않는다.

### 61. Primary Key (기본키)

-   **한 줄 뜻:** 행을 고유하게 식별하는 키
-   **쉽게:** 각 지식에 붙은 중복 없는 번호다.
-   **예시·기억:** id=102가 서버 실행 자료를 가리킨다.

### 62. Metadata (메타데이터)

-   **한 줄 뜻:** 자료를 설명하거나 분류하는 정보
-   **쉽게:** 책의 제목 옆에 분야나 판본을 적는 것과 같다.
-   **예시·기억:** category, source_version, embedding_model.

### 63. Metadata Filter

-   **한 줄 뜻:** 메타데이터 조건으로 검색 범위를 제한하는 것
-   **쉽게:** 도서관에서 개발 분야 책만 찾는 것과 같다.
-   **예시·기억:** WHERE category = 'development'.

### 64. Source Version

-   **한 줄 뜻:** 원문 데이터의 버전
-   **쉽게:** 어느 판본의 자료인지 추적하는 표시다.
-   **예시·기억:** knowledge_v1과 knowledge_search_v2.

### 65. Upsert

-   **한 줄 뜻:** 없으면 삽입하고 충돌하면 갱신하는 방식
-   **쉽게:** 같은 ID 자료가 있으면 기존 행을 업데이트한다.
-   **예시·기억:** INSERT ... ON CONFLICT (id) DO UPDATE.

### 66. Top-k Search

-   **한 줄 뜻:** 가장 가까운 후보를 최대 k개 반환하는 검색
-   **쉽게:** 검색 결과 상위 몇 개만 가져온다.
-   **예시·기억:** k=3이면 최대 3개이지 정답 3개가 아니다.

### 67. Nearest Neighbor (최근접 이웃)

-   **한 줄 뜻:** 질의 벡터와 가까운 벡터
-   **쉽게:** 지도에서 내 위치와 가까운 지점을 찾는 것과 같다.
-   **예시·기억:** 코사인 거리가 작은 문서가 먼저 나온다.

### 68. Distance Operator (거리 연산자)

-   **한 줄 뜻:** DB에서 벡터 간 거리를 계산하는 기호
-   **쉽게:** 어떤 방식으로 비교할지 선택하는 계산 기호다.
-   **예시·기억:** \<=\> 코사인 거리, \<-\> L2 거리, \<#\> 음의 내적.

### 69. Operator Class

-   **한 줄 뜻:** 인덱스가 사용할 연산 방식의 정의
-   **쉽게:** 인덱스와 검색 계산의 규칙을 맞춘다.
-   **예시·기억:** 코사인 거리에는 vector_cosine_ops.

### 70. LIMIT

-   **한 줄 뜻:** SQL 결과 최대 개수를 지정하는 절
-   **쉽게:** 가까운 순서로 정렬한 뒤 몇 개만 꺼낸다.
-   **예시·기억:** LIMIT 3.

### 71. Parameter Binding (파라미터 바인딩)

-   **한 줄 뜻:** SQL 문과 전달할 값을 분리하는 방식
-   **쉽게:** 빈칸에 값을 안전하게 채워 실행한다.
-   **예시·기억:** %s에 qvec과 k를 순서대로 전달한다.

### 72. SQL Injection

-   **한 줄 뜻:** 입력값이 SQL 명령으로 해석되어 발생하는 보안 문제
-   **쉽게:** 검색값이 명령문 자체를 바꾸지 않도록 해야 한다.
-   **예시·기억:** 값은 문자열 결합 대신 파라미터 바인딩으로 전달한다.

## 6. Vector Index · HNSW

### 73. Vector Index (벡터 인덱스)

-   **한 줄 뜻:** 벡터 검색을 효율적으로 수행하도록 돕는 구조
-   **쉽게:** 책의 색인처럼 후보를 찾는 시간을 줄인다.
-   **예시·기억:** 오늘은 HNSW를 선택 실습으로 다룬다.

### 74. Exact Search (정확 검색)

-   **한 줄 뜻:** 모든 비교 대상의 거리를 계산하는 검색
-   **쉽게:** 모든 후보를 직접 비교해 가까운 순서로 정렬한다.
-   **예시·기억:** 9개 자료라면 정확 검색으로 충분하다.

### 75. ANN (Approximate Nearest Neighbor)

-   **한 줄 뜻:** 근사 최근접 이웃 검색
-   **쉽게:** 일부 후보를 탐색해 빠르게 가까운 자료를 찾는다.
-   **예시·기억:** 정확 검색의 상위 후보를 놓칠 수 있다. 인공신경망의 ANN과 다르다.

### 76. HNSW

-   **한 줄 뜻:** 계층형 그래프로 후보를 탐색하는 ANN 인덱스
-   **쉽게:** 큰 길에서 작은 길로 이동하듯 가까운 후보를 좁혀 나간다.
-   **예시·기억:** USING hnsw (embedding vector_cosine_ops).

### 77. IVFFlat

-   **한 줄 뜻:** 목록 기반 근사 벡터 인덱스
-   **쉽게:** 후보를 묶어 탐색하는 다른 방식이다.
-   **예시·기억:** 오늘은 비교 개념으로 소개된다.

### 78. Query Planner (쿼리 플래너)

-   **한 줄 뜻:** SQL 실행 방법을 결정하는 DB 구성 요소
-   **쉽게:** DB가 어떤 길로 자료를 찾을지 정한다.
-   **예시·기억:** 작은 테이블에서는 HNSW가 있어도 Seq Scan을 선택할 수 있다.

### 79. Seq Scan

-   **한 줄 뜻:** 테이블의 행을 순차적으로 읽는 실행 방식
-   **쉽게:** 자료를 처음부터 차례로 확인한다.
-   **예시·기억:** 9건에서는 정상적인 선택일 수 있다.

### 80. EXPLAIN

-   **한 줄 뜻:** DB가 선택한 실행 계획을 보여주는 SQL
-   **쉽게:** 검색이 어떤 방법으로 실행될지 확인한다.
-   **예시·기억:** 인덱스 사용 여부를 확인한다.

### 81. EXPLAIN ANALYZE

-   **한 줄 뜻:** 쿼리를 실제 실행하고 실행 정보를 보여주는 명령
-   **쉽게:** 예상 계획뿐 아니라 실제 실행 결과를 확인한다.
-   **예시·기억:** SELECT를 실제로 실행한다는 점을 기억한다.

### 82. Cost

-   **한 줄 뜻:** 플래너의 예상 실행 비용
-   **쉽게:** 실행 방법 비교용 추정 단위다.
-   **예시·기억:** 밀리초가 아니다.

### 83. m / ef_construction

-   **한 줄 뜻:** HNSW 생성 시 연결 수와 탐색 폭에 영향을 주는 설정
-   **쉽게:** 인덱스를 만들 때 길의 연결과 탐색 범위를 조절한다.
-   **예시·기억:** 자원 사용과 검색 품질에 영향이 있다.

### 84. ef_search

-   **한 줄 뜻:** HNSW 검색 시 후보 탐색 폭 설정
-   **쉽게:** 검색 중 얼마나 넓게 살펴볼지 정한다.
-   **예시·기억:** 폭을 높이면 누락이 줄 수 있지만 시간과 자원이 증가한다.

### 85. Iterative Scan

-   **한 줄 뜻:** 근사 검색에서 추가 탐색을 수행하는 기능
-   **쉽게:** 필터 통과 후보가 부족하면 더 찾아볼 수 있게 돕는다.
-   **예시·기억:** pgvector 0.8.x에서 도움을 줄 수 있지만 완전 보장은 아니다.

## 7. Retrieval 결과 평가

### 86. Relevance (관련성)

-   **한 줄 뜻:** 원문이 질문의 요구에 맞는 정도
-   **쉽게:** 비슷한 주제인지보다 필요한 사실이 실제 있는지 본다.
-   **예시·기억:** 서버 실행 위치 질문에 102는 관련 자료다.

### 87. Partially Relevant (부분 관련)

-   **한 줄 뜻:** 주제는 맞지만 필요한 사실이 빠진 상태
-   **쉽게:** 질문에 필요한 정보 중 일부만 있는 경우다.
-   **예시·기억:** 보관 기간 질문에 보관 위치만 알려주는 101.

### 88. Irrelevant (무관)

-   **한 줄 뜻:** 후보가 있어도 질문 해결에 필요한 사실이 없는 상태
-   **쉽게:** 검색은 됐지만 사용할 답변 근거가 없다.
-   **예시·기억:** 필요한 날짜나 기간이 원문에 없다.

### 89. Qualitative Evaluation (정성평가)

-   **한 줄 뜻:** 사람이 원문과 질문을 비교해 품질을 판단하는 평가
-   **쉽게:** 점수만 보는 대신 실제 내용을 읽고 이유를 기록한다.
-   **예시·기억:** 관련·부분 관련·무관으로 분류한다.

### 90. Out-of-scope Question (범위 밖 질문)

-   **한 줄 뜻:** 자료가 지원하지 않는 질문
-   **쉽게:** 도서관에 없는 정보를 묻는 상황이다.
-   **예시·기억:** 파일 보관 기간이 자료에 없다면 추측하지 않는다.

### 91. Empty Result

-   **한 줄 뜻:** 정상적으로 검색했지만 결과가 없는 상태
-   **쉽게:** 조회 자체는 성공했으나 조건에 맞는 자료가 없다.
-   **예시·기억:** rows=\[\].

### 92. Error

-   **한 줄 뜻:** 검색 실행이 실패한 상태
-   **쉽게:** 검색 결과가 없는 것이 아니라 검색 자체가 실패했다.
-   **예시·기억:** DB 연결 오류, SQL 오류, 벡터 차원 오류.

### 93. Reproducibility (재현성)

-   **한 줄 뜻:** 같은 조건에서 결과를 다시 확인할 수 있는 성질
-   **쉽게:** 실험할 때 사용한 조건을 기록해 두는 것이다.
-   **예시·기억:** 모델 revision, 원문 버전, k, 필터를 기록한다.

### 94. Recall@k / MRR / nDCG

-   **한 줄 뜻:** 검색 품질을 평가하는 지표 이름
-   **쉽게:** 검색 결과의 발견 여부와 순위 품질 등을 평가하는 후속 개념이다.
-   **예시·기억:** 정식 지표는 25일 수업 범위로 오늘은 정성평가에 집중한다.

## 8. Agent 검색 모듈과 RAG 연결

### 95. Search Module (검색 모듈)

-   **한 줄 뜻:** 질문을 받아 관련 후보를 반환하는 독립 구성 요소
-   **쉽게:** 검색 작업을 담당하는 부품이다.
-   **예시·기억:** 오늘은 GPT 호출 없이 ID·제목·본문·거리를 반환한다.

### 96. Input / Output Contract

-   **한 줄 뜻:** 함수의 입력과 반환값에 대한 약속
-   **쉽게:** 부품끼리 연결할 때 맞춰야 하는 규격이다.
-   **예시·기억:** 질문·k·필터를 받아 후보 목록을 반환한다.

### 97. Context

-   **한 줄 뜻:** LLM에 실제로 전달하는 정보
-   **쉽게:** 검색된 책 중 현재 답변을 위해 책상에 올려놓은 자료다.
-   **예시·기억:** 검색된 후보 전부를 넣을 필요는 없다.

### 98. retrieved_ids

-   **한 줄 뜻:** 검색으로 가져온 후보의 ID 집합
-   **쉽게:** 사서가 찾아온 책 전체다.
-   **예시·기억:** \[101,102,107\].

### 99. included_ids

-   **한 줄 뜻:** 검토 후 실제 Context에 넣은 자료 ID 집합
-   **쉽게:** 찾은 책 중 읽을 책만 선택한 것이다.
-   **예시·기억:** \[102\].

### 100. source_ids

-   **한 줄 뜻:** 최종 응답에서 인용한 자료 ID 집합
-   **쉽게:** 답변에서 실제 출처로 밝힌 책이다.
-   **예시·기억:** \[102\], included_ids 안에 있어야 한다.

### 101. Citation (출처 인용)

-   **한 줄 뜻:** 답변 근거가 된 자료를 표시하는 일
-   **쉽게:** 어디서 확인한 사실인지 알려준다.
-   **예시·기억:** ID뿐 아니라 실제 본문 근거도 검증한다.

### 102. KnowledgeAnswer

-   **한 줄 뜻:** 이전 수업에서 사용한 답변 검증용 출력 계약
-   **쉽게:** 답변의 상태와 근거를 정해진 형식으로 전달한다.
-   **예시·기억:** 검색되었다는 이유만으로 answered를 확정하지 않는다.

### 103. insufficient_context

-   **한 줄 뜻:** 답변 근거가 부족한 상태
-   **쉽게:** 찾은 자료에 필요한 정보가 없어서 답을 확정할 수 없다.
-   **예시·기억:** 보관 위치만 있고 기간이 없는 경우.

### 104. RAG (Retrieval-Augmented Generation)

-   **한 줄 뜻:** 검색으로 확보한 자료를 이용해 LLM 답변을 생성하는 방식
-   **쉽게:** 관련 자료를 찾아 읽힌 뒤 답을 작성하게 하는 구조다.
-   **예시·기억:** 오늘은 Retrieval, 20일에 Context와 LLM을 연결한다.

### 105. Parsing / Chunking

-   **한 줄 뜻:** 문서 내용을 추출하는 작업 / 문서를 작은 단위로 나누는 작업
-   **쉽게:** 긴 책에서 내용을 꺼내 적당한 분량으로 나누는 과정이다.
-   **예시·기억:** 19일 인덱싱 수업에서 다룬다.

### 106. Indexing Pipeline

-   **한 줄 뜻:** 문서를 검색 가능한 형태로 준비하는 작업 흐름
-   **쉽게:** 자료를 정리해 검색용 DB에 등록하는 과정이다.
-   **예시·기억:** 파싱 → 정제 → Chunking → Metadata → Embedding → 저장.

### 107. Hybrid Search / Reranking

-   **한 줄 뜻:** 키워드와 의미 검색을 결합하는 방식 / 후보 순위를 다시 평가하는 방식
-   **쉽게:** 서로 다른 검색 방식을 함께 쓰고 후보 순서를 다시 검토한다.
-   **예시·기억:** 23일 Hybrid, 24\~25일 개선·평가 수업에서 다룬다.

## 9. 헷갈리는 개념 비교

  -----------------------------------------------------------------------------------------
  구분                                핵심 차이
  ----------------------------------- -----------------------------------------------------
  Token vs Embedding 차원             토큰은 입력 텍스트 조각, 차원은 출력 벡터 숫자 개수

  LLM vs Embedding 모델 vs pgvector   답변 생성 vs 벡터 생성 vs 저장·검색

  Similarity vs Distance              큰 값 우선 vs 작은 값 우선

  Dot vs Cosine                       벡터 길이 영향 vs 방향 중심

  L2 norm vs L2 distance              벡터 자체 길이 vs 두 벡터 사이 거리

  query vs passage                    E5 질문 입력 vs 문서 입력

  Exact vs ANN                        전체 비교 기준선 vs 근사 후보 탐색

  Retrieval vs Context vs Citation    검색 후보 vs 전달 자료 vs 최종 인용 자료

  empty vs error vs irrelevant        정상 빈 결과 vs 실행 실패 vs 근거 부족
  -----------------------------------------------------------------------------------------

### 숫자로 이해하는 유사도와 거리

q=(1,0), a=(0.8,0.6)일 때:

-   Dot = 1×0.8 + 0×0.6 = 0.8
-   두 벡터의 길이는 각각 1이므로 Cosine similarity = 0.8
-   Cosine distance = 1 − 0.8 = 0.2
-   L2 distance = √((1−0.8)² + (0−0.6)²) ≈ 0.6325

단위 벡터에서는 Dot = Cosine similarity이고 L2² = 2 − 2×Cosine similarity이므로 가까운 순서가 같다. 임의 벡터에서는 이 관계를 가정하지 않는다. 유사도 0.8은 정답 확률 80%가 아니다.

### pgvector 설치 4단계 비교

  -----------------------------------------------------------------------------------
  단계                       실행 위치                 확인
  -------------------------- ------------------------- ------------------------------
  서버 확장 파일 빌드·설치   관리자 x64 Native Tools   DLL·control·SQL 파일

  DB 활성화                  pgAdmin                   CREATE EXTENSION, extversion

  Python 패키지 설치         Git Bash, 기존 가상환경   pip show, pip check

  연결별 타입 등록           Python                    register_vector(conn)
  -----------------------------------------------------------------------------------

원본의 Windows 빌드 후보는 v0.8.7이며 실제 PC 성공 여부는 별도 검증이 필요하다. 전체 설치 명령과 오류 대응은 원본 4장을 참고한다.

### 핵심 검색 코드 읽기

``` sql
SELECT id, title, content,
       embedding <=> %s AS distance
FROM day23_search_docs
ORDER BY embedding <=> %s ASC
LIMIT %s;
```

-   `<=>`는 코사인 거리 계산이다.
-   `ASC`는 거리가 작은 순서다.
-   같은 질의 벡터를 두 번 전달하며 마지막 값은 k다.
-   검색 결과가 나와도 원문을 읽고 근거 적합성을 판단한다.
