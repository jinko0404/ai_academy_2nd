RAG 문서처리 전체 흐름 정리
작성자 : 고진석

1. 원본 문서를 준비한다.(Raw)
	- 원본 파일은 컴퓨터의 지정된 폴더에 보관하고, Python 코드에서 이를 읽도록 만들 수 있다.

2.원본 파일에서 내용을 추출한다.(Parsing)
	- 원본 파일이 준비되었다면 이제 Python 코드에서 파일을 읽어야한다.
	- 각 파일의 종류(HTML, Markdown, PDF 등)에 따라 내부 형식이 다르기에 읽는 방법도 달라진다.
		- TXT: 글자를 그대로 읽는다.
		- Markdown: 글자와 제목 구조를 파악한다.
		- HTML: HTML 요소에서 본문을 추출한다.
		- PDF: 페이지별 텍스트를 추출한다.
		- 스캔 PDF: 이미지 속 글자를 읽기 위해서는 OCR이 필요하다
			* OCR : 이미지나 스캔된 문서 속에 있는 텍스트를 컴퓨터가 편집하고 검색할 수 있는 텍스트 데이터로 변환하는 기술
	- 위 과정을 거치고 파일에서 추출된 페이지나 절 단위의 자료를 ParsedUnit이라고 한다.
		- Raw File = 원본 파일
		- ParsedUnit = 파일을 읽어서 추출한 내용과 구조

3. 추출한 글을 정리한다.(Cleaning)
	- ParsedUnit 과정을 통해 불필요한 공백이나 줄바꿈 형식을 정리할 수 있다.
	- 이 과정을 거친 정리된 내용을 담은 단위를 CleanUnit이라고 한다.
	- 다만 불필요한 형식을 정리하는 작업이지 문장의 의미를 바꾸는 작업이 아니기에 이를 주의하며 작업해야한다.

4. 정리된 문서를 작은 단위로 나눈다.(Chunking)
	- 문서의 양이 많을 때 필요한 부분만 정확하게 찾기 어렵고, 모델의 입력 길이 제한도 걸릴 수 있기에 문서를 적절한 크기로 나눈다.
	- 이 같은 작업을 Chunking이라고 하며 이 작업을 통해 나뉜 결과물 하나 하나를 Chunk 라고한다.

5. 저장 전에 검사하고 출저를 붙인다.
	- 만들어진 Chunk는 모두 올바른 문서인지 아니면 오류가 있는지 검사하기 전이기에 이를 검토하는 작업은 꼭 필요하다.
	- 만들어진 Chunk는 파이썬 코드에서 검사 작업이 진행되고, 검사를 통과하지 못하면 사유가 기록되고 정상 검색 대상에서 제외되	거나 수정 후 다시 처리된다.
	- 검사가 통과된 Chunk는 해당 데이터가 어디에서 왔는지 설명하는 부가정보가 적힌 Metadata가 부여된다.
	- Retriever를 통해 검색된 문서가 어디에서 나왔는지 추적할 수 있어야 되기에 Metadata는 꼭 필요한 정보다.

6. Chunk를 숫자 Vector로 변환한다.(E5 Embedding)
	- 위 모든 과정을 거친 Chunk는 파이썬 코드에 의해 Embedding 모델에 전달이 된다.
	- Embedding 과정은 나중에 사용자 질문을 숫자 벡터로 변환 했을 때 문서 벡터들과 얼마나 가까운지 계산하기 위해서 꼭 필요하다.

7 Chunk와 벡터를 저장하고 공개한다
	- Embedding을 통해 숫자 벡터로 변환된 Chunk는 pgvector를 통해 PostgreSQL에 저장된다.
	- 이 과정에서 저장 하기 전에 새 자료를 검토하는 과정이 있는데 검토 중에 문제가 있으면 공개가 중단된다.

8. 위와 같은 과정을 겪고 DB에 저장된 데이터는 추후 사용자 질문이 들어왔을 때 질문 처리 과정에서 사용된다.
