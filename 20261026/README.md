## 1. 회귀와 분류

| 구분 | Regression (회귀) | Classification (분류) |
|---|---|---|
| 목적 | 숫자 자체를 예측 | 데이터가 속할 클래스 예측 |
| 예시 | 작업 소요 시간 예측 | 작업 성공·실패 예측 |
| 예측 결과 | 연속적인 숫자 | 클래스 또는 클래스별 확률 |

**핵심:** 예측하려는 정답이 숫자 자체인지, 종류를 구분하는 것인지에 따라 회귀와 분류를 구분합니다.

## 2. 선형회귀와 회귀 평가 지표

### 2-1. 선형회귀 (Linear Regression)

입력 특성과 정답 사이의 관계를 학습하여 숫자를 예측하는 모델입니다.

예시: 작업의 입력 특성을 바탕으로 예상 소요 시간(`elapsed_ms`)을 예측합니다.

### 2-2. 회귀 평가 지표

| 지표 | 의미 | 해석 |
|---|---|---|
| MAE | 평균 절대 오차 | 실제값과 예측값의 절대 오차 평균 |
| MSE | 평균 제곱 오차 | 오차를 제곱한 값의 평균 |
| RMSE | 평균 제곱근 오차 | MSE에 제곱근을 적용한 값 |
| R² | 결정계수 | 모델이 실제 데이터의 변동을 얼마나 설명하는지 나타내는 지표 |

- **MAE (Mean Absolute Error)**: 예측값이 실제값에서 평균적으로 얼마나 벗어났는지 나타냅니다.
- **MSE (Mean Squared Error)**: 오차를 제곱하므로 큰 오차에 더 큰 페널티를 부여합니다.
- **RMSE (Root Mean Squared Error)**: MSE에 제곱근을 적용하여 원래 정답과 같은 단위로 해석할 수 있습니다.
- **R² (Coefficient of Determination)**: 일반적인 회귀 평가에서는 값이 높을수록 좋으며, 1에 가까울수록 데이터의 변동을 잘 설명합니다. 음수가 나올 수도 있습니다.

> **기억할 점:** MAE와 RMSE는 일반적으로 낮을수록 좋고, R²는 일반적으로 높을수록 좋습니다. RMSE는 큰 오차에 상대적으로 더 민감합니다.

## 3. 로지스틱 회귀와 분류 평가 지표

### 3-1. 로지스틱 회귀 (Logistic Regression)

이름에는 회귀가 들어가지만, 일반적으로 **분류 문제**에 사용하는 모델입니다.

예시: 작업이 성공했는지 실패했는지 예측합니다.

### 3-2. 혼동행렬 (Confusion Matrix)

실제 정답과 모델의 예측을 비교하여 어떤 종류의 오류가 발생했는지 확인합니다.

실패를 양성 클래스(1), 성공을 음성 클래스(0)로 설정한 경우입니다.

| 실제 \ 예측 | 성공 예측 (0) | 실패 예측 (1) |
|---|---|---|
| 실제 성공 (0) | TN: 성공을 성공으로 예측 | FP: 성공을 실패로 잘못 예측 |
| 실제 실패 (1) | FN: 실패를 성공으로 잘못 예측 | TP: 실패를 실패로 예측 |

- **TN (True Negative)**: 성공을 성공으로 맞힘
- **FP (False Positive)**: 성공을 실패로 잘못 판단 — 오탐
- **FN (False Negative)**: 실패를 놓치고 성공으로 잘못 판단 — 미탐
- **TP (True Positive)**: 실패를 실패로 맞힘

> 이 문서에서는 실패(1)를 찾아내는 것을 목표로 설정했습니다. 따라서 FP와 FN의 의미는 어떤 클래스를 양성(1)으로 설정했는지에 따라 달라질 수 있습니다.

### 3-3. 분류 평가 지표

| 지표 | 의미 | 확인할 질문 |
|---|---|---|
| Accuracy | 정확도 | 전체 예측 중 맞힌 비율은? |
| Precision | 정밀도 | 실패라고 예측한 것 중 실제 실패는 얼마나 되는가? |
| Recall | 재현율 | 실제 실패 중 얼마나 찾아냈는가? |
| F1-score | F1 점수 | 정밀도와 재현율을 함께 고려하면 어떤가? |

- **Accuracy**: 전체 예측 중 정답을 맞힌 비율입니다.
- **Precision**: 실패라고 예측한 결과의 신뢰도를 나타냅니다.
- **Recall**: 실제 실패 사례를 얼마나 놓치지 않고 찾아냈는지 나타냅니다.
- **F1-score**: Precision과 Recall의 조화평균으로, 두 지표를 함께 고려합니다.

> **주의:** 실패 사례가 적은 데이터에서는 Accuracy만으로 모델을 평가하기 어려울 수 있습니다. 업무상 실패를 놓치는 비용이 크다면 Recall과 FN도 함께 확인해야 합니다.

## 4. KNN (K-Nearest Neighbors)

새로운 데이터와 가까운 기존 데이터 K개를 찾아, 그 사례를 참고해 예측하는 방식입니다.

### 4-1. 예측 순서

1. 새로운 데이터 입력
2. 기존 학습 데이터와의 거리 계산
3. 가까운 K개 이웃 탐색
4. 이웃의 정답을 참고하여 예측

| 문제 유형 | 예측 방식 |
|---|---|
| KNN 분류 | 이웃 클래스의 다수결 투표 |
| KNN 회귀 | 이웃 정답값의 평균 또는 가중평균 |

### 4-2. 주요 하이퍼파라미터

| 설정 | 의미 |
|---|---|
| `n_neighbors` | 참고할 이웃의 수 K |
| `weights="uniform"` | 모든 이웃을 동일한 가중치로 취급 |
| `weights="distance"` | 가까운 이웃에 더 큰 가중치 부여 |
| `p=1` | 맨해튼 거리 |
| `p=2` | 유클리드 거리 |

- **맨해튼 거리 (`p=1`)**: 격자에서 가로와 세로로 이동한 거리의 합처럼 계산합니다.
- **유클리드 거리 (`p=2`)**: 두 점 사이를 직선으로 연결한 거리처럼 계산합니다.

> KNN은 거리 계산에 영향을 받으므로 숫자 특성의 스케일이 크게 다르면 특정 특성이 거리에 과도한 영향을 줄 수 있습니다. 따라서 표준화 등의 전처리를 고려합니다.

## 5. 데이터 스케일링과 전처리

### 5-1. 혼동하기 쉬운 개념

| 개념 | 도구 | 역할 |
|---|---|---|
| 표준화 | `StandardScaler` | 평균과 표준편차를 이용해 특성의 척도를 변환 |
| 최소-최대 스케일링 | `MinMaxScaler` | 학습 데이터의 최솟값과 최댓값을 이용해 지정된 범위로 변환 |
| 벡터 정규화 | `Normalizer` | 각 행의 벡터 길이를 일정하게 조정 |
| 규제 | 예: `Ridge`, `Lasso` | 모델의 계수 등에 제약을 주어 과도한 복잡성을 억제 |

**주의:** 표준화와 최소-최대 스케일링은 특성의 척도를 변환하는 방법입니다. 규제는 모델의 복잡성을 억제하는 학습 방법으로, 서로 다른 개념입니다.

### 5-2. 전처리 파이프라인

숫자형 특성과 범주형 특성은 서로 다른 방식으로 전처리할 수 있습니다.

예를 들어 원본 입력이 숫자형 2개와 범주형 2개로 구성되어 있다면 다음과 같이 처리할 수 있습니다.

**숫자형 경로**
1. 결측값을 중앙값으로 대체 (`SimpleImputer`)
2. 표준화 또는 최소-최대 스케일링 적용

**범주형 경로**
1. 결측값을 최빈값으로 대체 (`SimpleImputer`)
2. 원-핫 인코딩 적용 (`OneHotEncoder`)

**전체 흐름**

`원본 데이터 → ColumnTransformer → 모델`

- `ColumnTransformer`: 열의 종류에 따라 서로 다른 전처리를 적용하고 결과를 결합합니다.
- `Pipeline`: 전처리 단계와 모델을 하나의 흐름으로 연결합니다.

`Pipeline` 안에 `ColumnTransformer`와 모델을 함께 구성하면 전처리와 학습을 일관되게 수행할 수 있습니다.

> **데이터 누수 방지:** 전처리 기준은 학습 데이터로 학습해야 합니다. 검증·테스트 데이터의 정보를 미리 사용하지 않도록 주의합니다.

## 6. 학습 파라미터와 하이퍼파라미터

| 구분 | 예시 | 결정 방식 |
|---|---|---|
| 학습 파라미터 | 선형회귀의 계수와 절편 | `fit()`을 통해 데이터에서 학습 |
| 하이퍼파라미터 | KNN의 K, 가중치, 거리 설정 | 후보를 정하고 검증 데이터로 비교 |
| 전처리 설정 | 표준화, Min-Max, 스케일링 없음 | 실험 조건을 정하고 비교 |
| 판단 정책 | 실패로 판정할 확률 임계값 | 오류 비용과 검증 결과를 고려 |

- **학습 파라미터**는 모델이 학습 과정에서 데이터로부터 알아내는 값입니다.
- **하이퍼파라미터**는 학습 전에 설정하거나 검증을 통해 선택하는 값입니다.
- **전처리 설정** 역시 비교 실험에서 선택할 수 있습니다.
- **확률 임계값**은 분류 확률을 실제 클래스로 바꾸는 기준입니다. 예를 들어 실패 확률이 0.5 이상이면 실패(1)로 판단할 수 있습니다.

## 7. 기준선 모델과 과적합·과소적합

### 7-1. 기준선 모델 (Baseline)

복잡한 모델의 성능을 판단하려면 단순한 기준선과 비교해야 합니다.

| 문제 유형 | 기준선 모델 | 비교 모델 예시 |
|---|---|---|
| 회귀 | `DummyRegressor` | `LinearRegression`, `KNeighborsRegressor` |
| 분류 | `DummyClassifier` | `LogisticRegression`, `KNeighborsClassifier` |

- `DummyRegressor`: 기본 설정에서 학습 정답의 평균을 예측합니다.
- `DummyClassifier`: 기본 설정에서 가장 흔한 클래스를 예측합니다.

기준선보다 복잡한 모델의 성능이 좋지 않다면, 모델이나 전처리, 데이터의 특성을 다시 검토해야 합니다.

> **모델 선택 원칙:** 점수가 가장 높은 모델을 무조건 선택하지 않습니다. 사전에 정한 평가 지표와 실제 업무에서 발생하는 오류 비용을 함께 고려합니다.

### 7-2. 과적합과 과소적합

| 개념 | 의미 | 특징 |
|---|---|---|
| 과적합 (Overfitting) | 학습 데이터에 지나치게 맞춰진 상태 | 학습 성능은 좋지만 새로운 데이터에서 성능이 떨어짐 |
| 과소적합 (Underfitting) | 데이터의 패턴을 충분히 학습하지 못한 상태 | 학습 데이터와 새로운 데이터 모두에서 성능이 떨어짐 |

## 8. 프로젝트 구현 시 필요한 요소

| 항목 | 목적 |
|---|---|
| 모델 비교표 | 모델별 평가 지표와 설정을 기록 |
| 예측 결과 저장 | 데이터 ID, 실제값, 예측값을 함께 저장 |
| 오류 분석 | 큰 회귀 오차와 FP·FN 사례를 확인 |
| 자동 검사 | 필수 열, 행 수, K 범위, 전처리 상태 등을 확인 |
| 모델 저장·복원 | 학습한 모델을 저장하고 다시 불러오기 |
| 재현성 확보 | README, 패키지 버전, 데이터 분할 ID, Git 변경 이력 기록 |
| 최종 평가 | 모델 선택이 끝난 후 테스트 데이터로 최종 성능 확인 |

### 모델 저장 및 복원 예시

```python
import joblib

# 모델 저장
joblib.dump(model, "model.joblib")

# 모델 복원
loaded_model = joblib.load("model.joblib")
```

### 데이터 분리와 최종 평가 원칙

- **학습 데이터 (Train)**: 모델과 전처리 기준을 학습합니다.
- **검증 데이터 (Validation)**: 모델, 하이퍼파라미터, 전처리 설정을 비교하고 선택합니다.
- **테스트 데이터 (Test)**: 선택이 끝난 모델의 최종 성능을 평가합니다.

테스트 데이터는 모델 선택 과정에서 반복적으로 사용하지 않습니다. 그래야 최종 성능을 보다 공정하게 평가할 수 있습니다.

## 📝 오늘의 핵심 정리

- 회귀는 숫자를 예측하고, 분류는 클래스를 예측합니다.
- 회귀는 MAE·MSE·RMSE·R², 분류는 Accuracy·Precision·Recall·F1 등을 활용합니다.
- 혼동행렬은 모델이 어떤 종류의 오류를 범했는지 보여줍니다.
- KNN은 가까운 이웃을 참고하므로 거리와 스케일링 설정이 중요합니다.
- `ColumnTransformer`는 특성별 전처리를 적용하고, `Pipeline`은 전처리와 모델을 연결합니다.
- 기준선 모델과 비교하고, 검증 데이터로 모델을 선택한 뒤 테스트 데이터로 최종 평가합니다.
- 좋은 모델을 만드는 것뿐 아니라 결과 저장, 오류 분석, 자동 검사, 재현성 확보도 중요합니다.
