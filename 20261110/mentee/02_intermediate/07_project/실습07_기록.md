# 실습 07 · 함께 확인한 결과

초기 3건에서 정확히 한 번 등록했을 때만 id=4입니다. 응답에서 받은 ID를 기록하세요.
※ 아래 결과는 초기 데이터를 복사한 임시 knowledge.json을 TestClient로 확인한 기록이며, 실제 작업 파일은 변경하지 않았다.
실제 ID: 4 (임시 데이터 검증 기준)

| 동작 | 예상 | 실제 | 파일 확인 |
|---|---|---|---|
| 정상 등록 | 201, 새 id | 201, id=4 | 임시 knowledge.json 새 항목 추가, next_id 1 증가 |
| 같은 id 상세 조회 | 200, 등록 내용 | 200, id=4의 등록 내용 반환 | 임시 knowledge.json 조회 전후 파일 변경 없음 |
| 같은 id 본문 수정 | 200, 같은 id | 200, id=4의 수정 내용 반환 | 임시 knowledge.json 본문 변경, ID·next_id·항목 수 유지 |
| 없는 id 수정 (정상 Body) | 404 | 404 | 변경 사항 없음 |
| content 빈 문자열 등록 | 422, 파일 불변 | 422, 파일 불변 | 422 응답 반환 후 변경 사항 없음 |
| 같은 id 삭제 | 204, 빈 본문 | 204, 빈 본문 반환 | 임시 knowledge.json의 id=4 항목 삭제 |
| 삭제한 id 조회 | 404 | 404, {"detail": "Knowledge not found"} 반환 | 조회 후 임시 knowledge.json 변경 사항 없음 |

응답의 성공과 파일 저장 성공을 어떻게 함께 확인했는가: TestClient로 상태코드(조회·수정: 200, 등록: 201, 삭제: 204)와 오류 응답(404·422)을 확인한 후, 임시 JSON 파일을 읽어 데이터 변경 또는 유지 여부를 확인했다.

이 API는 지식을 관리하는가, 질문의 답변을 생성하는가: 지식 목록 데이터를 조회(전체·상세·category별), 수정, 삭제, 추가하는 CRUD 관리 API다. 질문의 답변을 생성하는 기능은 없다.
